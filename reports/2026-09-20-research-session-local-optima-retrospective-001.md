## Question

Across this session, where did a productive first line of inquiry cause the audit to become locally satisfied too early?

The standard is not:

> was the first finding wrong?

Most were right.

The harder question is:

> what adjacent failure class became less visible because the first finding gave us a satisfying abstraction, repair, or vocabulary?

## Meta-finding

The recurring local optimum was:

**representation before closure.**

The session repeatedly succeeded at making a concept explicit:

- shared semantic owner;
- structured state;
- authored edge;
- observability axis;
- rival list;
- independence vector;
- support envelope;
- canonical authority.

Then the audit often paused before asking how that concept behaves:

- across multiple authorities during a transition;
- after an upstream dependency becomes stale;
- when the named alternatives omit the real explanation;
- when measurement perturbs the measured process;
- when quantitative thresholds drift from the frozen design;
- when a transfer source supports the mechanic but not the target regime;
- when different artifacts contain complementary rather than duplicate knowledge;
- when a question-generation method itself has blind spots.

The corrective heuristic is therefore:

> **After the first productive representation or ownership result, perform one explicit closure pass.**

## 1. Domain bones: semantic convergence was only the first anatomy

### First productive line

The original connective-tissue-versus-bones question quickly exposed small repeated semantic invariants:

- semantic identity;
- claim/dependency;
- research-question contract;
- evidence applicability;
- population identity;
- observation integrity.

This was highly productive and became the center of the first implementation pass.

### What that focus initially hid

The important missing structure was not only shared datatypes.

Two adjacent classes appeared later:

1. **authority ownership** — several otherwise-valid artifacts could appear to own current state;
2. **relationship ownership** — tools inferred scientific edges from names, paths, co-location, or lexical similarity.

Those were not naturally visible through the “find repeated semantic helper” lens.

### Later correction

Subsequent passes explicitly audited authority and relation ownership and repaired:

- structured closeout authority;
- execution/question relationship semantics;
- authored-versus-discovered artifact edges;
- referential integrity;
- promotion decision evidence;
- question acquisition relations.

### Still underexplored branch

**Cross-authority transition coherence.**

Knowing who owns each fact does not prove that a scientific transition updates all affected owners coherently.

A closeout may legitimately touch:

- report disposition;
- question lifecycle;
- current workstream gate;
- experiment/promotion disposition;
- production realization provenance.

The integration audit catches several impossible end states, but there is no general transition object and none should be added yet.

**Trigger:** two materially different closeouts produce the same class of half-applied multi-authority transition that current integration checks cannot express.

## 2. Prose authority: categorical state distracted from quantitative authority

### First productive line

The prose audit found operational state being inferred from rhetoric:

- opt-in promotion state;
- workstream execution state;
- question lifecycle;
- report-local disposition.

Converting those to explicit machine categories was clearly correct.

### What that focus hid

Decision-bearing **numbers and identities** can be prose/config APIs too:

- thresholds;
- caps;
- sample sizes;
- action/config identities;
- decision cut points;
- work/node envelopes.

These can drift even when categorical state is perfectly structured.

### Concrete miss found in this retrospective

The reserve-starvation preflight said the reducer verified prespecified:

- 75M reserve threshold;
- 300M total-node threshold;
- canonical admissible-order action.

But those values were owned by reducer defaults and repeated in prose. The frozen sample did not machine-own them.

### Correction in this pass

The frozen reserve sample now carries:

`probeDesign.reserveNodes`
`probeDesign.totalNodes`
`probeDesign.expectedAction`

The reducer consumes those values from the frozen sample and rejects disagreeing CLI overrides.

Operating-model rule 23 now requires decision-bearing quantitative design to travel with the frozen scientific contract.

### General lesson

The prose lens must ask both:

- is categorical meaning hidden in prose?
- is quantitative/protocol meaning duplicated outside the frozen contract?

## 3. Relation authority: edge existence distracted from edge lifecycle

### First productive line

The relation audit correctly focused on:

- authored IDs over lexical similarity;
- explicit bundle membership over sibling-file convention;
- foreign-key integrity;
- reciprocal calibration edges;
- provenance versus discovery links.

### What that focus hid

An edge can be real and resolvable yet later become scientifically stale.

Potential lifecycle questions include:

- was this edge valid only for a particular solver/config/population revision?
- does superseding evidence invalidate the relation or only narrow it?
- does a material dependency change require downstream review?
- is a relation historical provenance or current entitlement?

### Current evidence

The shared claim primitive can identify material dependency invalidation.

Structured closeouts can carry `claimRefs`.

But persisted claim capsules are not yet a broad durable substrate, and the integration audit does not attempt global claim-to-closeout invalidation propagation.

### Decision

Do **not** build a global invalidation registry now.

**Trigger:** durable claim capsules become common enough that two downstream authorities need machine detection of “still points at a materially invalidated claim.”

## 4. Observability: seeing the phenomenon distracted from observer reactivity

### First productive line

The observability envelope exposed:

- eligibility;
- opportunity;
- reach;
- participation;
- measurement support;
- fidelity;
- coverage;
- censoring.

This found real false-negative paths and earned a shared primitive.

### What that focus hid

A measurement can be supported and protocol-faithful while still changing the thing being measured.

Relevant perturbations include:

- search order;
- allocation;
- work accounting;
- timing;
- memory pressure;
- stage participation;
- scheduling/concurrency effects.

### Existing evidence that this is real

Search-loss/failure instrumentation already has representative calibration:

- compact telemetry around +0.46% aggregate wall overhead with exact outcome/work parity on the calibrated sample;
- rich capture around +10.32% and therefore deliberately selective/research-only.

The instrumentation plans already knew this locally. The general observability audit did not initially integrate it as a first-class question.

### Correction in this pass

Operating-model rule 24 now requires parity plus bounded overhead/volume evidence when instrumentation touches the measured path.

### Machine promotion?

Not yet.

A new `reactivity` observability axis is only earned if at least two resolution-envelope consumers need software to block interpretation on the same observer-perturbation semantics.

## 5. Identifiability: named rivals distracted from the rival-generation process

### First productive line

The identifiability audit paired:

- live rivals;
- discriminating observable;
- outcome interpretation;
- required observability.

That was the right next concept.

### What that focus hid

Identifiability is conditional on the declared rival set.

A perfect discriminator between A and B does not establish that:

- A and B are exhaustive;
- the omitted C would not produce the same observation;
- the ontology used to name A/B is itself adequate;
- the proposal process did not simply fail to generate the right alternative.

This reconnects directly to the earlier negative-space distinction between:

- priority-space failure;
- proposal-space / candidate-grammar failure.

### Correction in this pass

Operating-model rule 22 now says declared rival sets are **decision-bounded, not exhaustive by default**.

`liveRivals[]` must not silently become an ontology-completeness claim.

### Future structure

A machine `rivalSetScope` / rival-generation provenance field may eventually be useful, but it is not earned yet.

**Trigger:** two live questions need software to distinguish “decision-sufficient rival set” from “claimed exhaustive rival set” or need provenance about how alternatives were generated.

## 6. Independence: static support topology distracted from adaptive dependence through time

### First productive line

The independence pass correctly decomposed independence into multiple axes:

- sample/data;
- parent/family;
- source construction;
- decision seam;
- instrument implementation;
- analysis method;
- analyst/model;
- framing/context;
- ontology/vocabulary;
- critical code.

### What that focus hid

The vector describes channels at a point in an analysis.

It does not by itself capture **adaptive dependence accumulated through sequential research**:

- one study chooses the next population;
- that result chooses the next instrument;
- that instrument defines the next ontology;
- later “independent” confirmation is selected because of earlier outcomes.

Research-block consumption events and selection-history doctrine cover pieces of this, but the independence vector is not automatically derived from that lineage.

### Decision

Do not add a scalar dependence score or global adaptive-history model.

**Trigger:** a second decision-bearing analysis claims independent support while its source blocks have machine-recorded consumption lineage that should mechanically downgrade one or more independence dimensions.

## 7. Transportability: mechanic support was only one support dimension

### First productive line

The transportability audit found a real mismatch:

software knew topology was cross-construction before it knew whether topology could express the claim.

That led to the producer-owned topology support envelope and mechanic-support assessment.

### What that focus hid

Support is multidimensional:

- mechanics;
- grid/scale;
- topology family;
- outcome/reference support;
- relevant target-region overlap;
- target population conditioning.

The docs already warned about unsupported scale/topology, but the machine helper initially checked only mechanics.

### Correction in this pass

Generator support assessment now evaluates separately:

- required mechanics;
- required grid sizes;
- required topology families.

Topology's supported family is explicit, and unsupported families remain explicit.

This extends the existing support helper rather than creating a generic transportability object.

### Still open

**Target overlap / representativeness** remains claim-relative.

A source can technically support the mechanic and topology but still poorly overlap the target response/geometry regime.

That deserves a future audit when a real transfer decision depends on it. It should not be inferred from source novelty alone.

## 8. Distributed knowledge: duplicate truth distracted from complementary truth

### First productive line

The distributed-knowledge audit interpreted:

> the repo already knows X, but the knowledge is scattered across...

primarily as duplicate semantic/authority knowledge.

That found real issues:

- evaluation evidence-role duplication;
- stale lifecycle vocabulary;
- producerAuthority prose/path mixtures;
- duplicated topology support lists;
- copied test wording/state tokens.

### What that focus hid

There is a second meaning of “scattered”:

> no artifact contains X; several different artifacts each contain a necessary piece, and X exists only as a join.

That is a **compositional knowledge** problem, not a deduplication problem.

### Existing architecture

The data-asset registry already authors many valuable relationships.

The relation-authority rule correctly forbids inferring scientific truth from lexical join-key overlap.

### Correction in this pass

Two cheap, scientifically bounded joins are now explicit:

1. **compact failure response + static descriptors + production boundary**
   - stratify failure phenotypes before buying rich traces;
   - nominate prospective descriptor-conditioned populations;
   - remain observational development evidence.

2. **compact failure response + variant families**
   - ask which controlled transformations move participation/work/progress phenotypes;
   - preserve parent-family dependence;
   - use recurrence across unrelated parents before generic claims.

### Next concept

A **latent-join audit** is earned as an audit method, not as an auto-edge generator.

It should ask:

- which current questions require facts split across assets?
- which assets already share an authored or safely constructible identity?
- what new question becomes answerable after the join?
- what dependence/selection boundary makes the join scientifically weaker than it looks?

Do not generate relation edges from string-overlapping join keys.

## 9. Negative-space / premise coverage: question quality distracted from question-generator calibration

### First productive line

The premise-map completeness and negative-space work did unusually strong things:

- independent reconstruction;
- reciprocal source coverage;
- discovery-yield saturation;
- ontology escapees;
- structurally silent questions;
- proposal-space versus priority-space distinctions.

### What remained underconnected

Those methods were mostly evaluated within their own premise-map program.

The broader research system now uses multiple question-generation routes:

- premise-map mining;
- archaeology;
- failure-response nominations;
- capability-memory contrasts;
- variant-family microscopes;
- exact/reference disagreements;
- negative-space audits;
- human/agent conceptual reconstruction.

The portfolio retrospective measures recent question answerability and some proposal provenance, but it does not yet identify the **proposal method** consistently enough to compare their yield, blind spots, redundancy, or decision value.

### Decision

Do not backfill speculative proposal-method labels onto historical questions.

Prospectively, when a stable question is admitted and the proposal path is known, retaining a small proposal-origin field may eventually let the system calibrate question-generation methods as instruments.

**Trigger:** at least two proposal methods produce enough stable questions that method-level yield/redundancy/answerability comparison could change which discovery method is used next.

## 10. Production realization: discovering a healthy organ almost ended the inquiry too early

### First productive line

A deeper realization audit correctly reversed the initial impulse to build a `ChangeRealization` registry.

Runtime default polarity, default equivalence, documentation checks, and specialist participation tests already form a meaningful organ.

### What could have been missed

A healthy realization organ does not automatically answer:

- which scientific decision licensed the change;
- which regression proof qualifies ordinary callers;
- what later evidence supersedes that qualification;
- what invalidation should force realization review.

### Later correction

The promoted/default-ON ledger gained a decision-evidence relation.

That is appropriately narrower than a realization registry.

### Remaining trigger

Only add more realization structure when a real consumer needs implementation-target identity, qualification state, supersession, or invalidation across multiple promotions.

## 11. Proxy assertions: convenient proxies repeatedly masqueraded as semantic tests

This retrospective itself exposed two small examples.

### Structured closeout count

The inventory test asserted:

> structured closeout evidence count >= 2

as a proxy for:

> the specific architectural reports we care about are indexed.

That proxy failed as the report set evolved.

The test now asserts explicit membership of the authority-ownership and distributed-knowledge closeouts.

### Alias parity attempt count

A solver alias-normalization test compared total attempts from two separate 50 ms wall-clock runs.

A 109 versus 110 attempt difference caused CI failure even though both aliases normalize through the same code path.

The test now compares the semantic object under test: the early-repair biased-tier node budget produced by legacy versus canonical aliases.

### Lesson

After any convenient aggregate/count/timing proxy is introduced, ask whether the assertion is actually about:

- identity;
- membership;
- semantic equality;
- protocol equivalence;
- or merely a correlated observable.

Prefer the owning semantic fact.

## Synthesis: where the next broad opportunities are

The missed branches cluster into four larger concepts.

### A. Contract completeness

Not merely “is there a machine contract?” but:

- does it own quantitative design?
- does it state whether rival coverage is open or exhaustive?
- does it include observer-reactivity qualification?
- does it carry target/support boundaries?

This is the next maturation of the scientific-contract idea.

### B. Transition coherence

Not merely “does every current fact have one owner?” but:

- when a decision changes several authorities, are the required transitions mutually coherent?
- can the repo detect a half-applied closeout before it becomes stale current state?

Do not build a transaction framework yet. Expand integration conformance only when concrete repeated transition failures appear.

### C. Compositional knowledge / latent joins

Not merely “centralize duplicated facts,” but:

- which different existing resources jointly answer a question that none can answer alone?

This is the strongest capability-expansion opportunity found in this retrospective because it can create new answerability without new solver compute or new instrumentation.

### D. Discovery-method calibration

Not merely “are questions represented and answerable?” but:

- which methods generate useful novel questions?
- which repeatedly rediscover the same conceptual basin?
- which produce expensive/unanswerable questions?
- which are blind to particular loci or abstraction levels?

This is a natural continuation of the premise-map discovery-yield work once enough prospective proposal provenance exists.

## Second-pass closure checklist

After any audit produces its first useful abstraction or repair, ask:

1. **Time:** what makes this fact stale?
2. **Transition:** what other authorities must change with it?
3. **Alternatives:** what omitted explanation would survive the new discriminator?
4. **Observer:** can measuring this change it?
5. **Numbers:** which thresholds/caps/identities determine interpretation, and who owns them?
6. **Target:** what population/regime does the evidence actually cover?
7. **Composition:** what additional fact becomes knowable only by joining another resource?
8. **Adaptation:** did earlier results choose this population/instrument/ontology?
9. **Invalidation:** if an upstream dependency changes, who notices downstream?
10. **Proxy:** is the test checking the semantic fact or a convenient correlate?

## Standing rule

**A productive first abstraction is the start of the second pass, not evidence that the lens is exhausted.**

The second pass should look for closure failures around that abstraction before adding more abstraction.
