> **Status:** concluded-positive
> **Last evidence:** 2026-09-18 — inspection of the existing producer/consumer seams named by `docs/solver-search-loss-evidence-implementation-plan.md` Phase 0, current HEAD.
> **Decision:** the plan's PR A scope (Phase 1 shared capsule contract + Phase 2 asset registry/relation discovery, no solver execution changes) is implemented in this pass. No existing generic artifact already carries every required capsule field, bounded retention, denominator semantics, lineage, and queryability together, so the "existing-resource collapse" stop condition (plan section 17) does not apply and a new `scripts/solver-search-loss-evidence-lib.mjs` contract is warranted.
> **Remaining gate:** Phase 3 (shared compact failure-response projection) and later phases remain unimplemented and unauthorized by this pass; they are separate PRs (B-E) per the plan's own rollout sequence.
> **Evidence role:** implementation record, not an experiment. No solver run, GHA dispatch, or research question is touched.
> **Population identity:** not applicable (design/contract freeze only).

## Frozen decisions (plan Phase 0, items 1-15)

1. **v1 compact failure-response fields / search-family extensions** — out of scope for this pass. The failure-response layer (plan 4.0) is Phase 3 / PR B, which requires touching solver-running workflows; this pass implements only the failure-observations and failure-annotations layers (capture/capsule contract), which do not depend on the failure-response layer existing first.
2. **Progress-over-work checkpoints in v1** — deferred to Phase 3 alongside decision 1, for the same reason; the capsule contract's `nodeProgress`/`workSpent`/`depth` fields already leave room for a producer to attach a progress summary later without a capsule schema change.
3. **Rejection-reason seams/vocabularies** — deferred to Phase 3's reason-seam audit (plan 4.7 "Rejection-reason composition"); this pass fixes only the `captureReason` selector vocabulary (decision 9 below), which is a different concept (why a row was *retained*, not why a candidate was *rejected*).
4. **Beam candidate-flow/frontier-summary fields** — deferred to Phase 3 (plan 4.7 "Candidate-flow accounting" and "Frontier diversity"); no solver instrumentation changes ship in this pass.
5. **Solved-run control collection semantics** — deferred to Phase 3/4; this pass's capsule contract does not distinguish solved-run from unsolved-run capsules structurally (a `disposition`/`captureReason` pair already can express either), so no schema change is anticipated when solved-run controls are added.
6. **Replayability classification/identity sources** — **frozen now**, because it is a capsule field, not a producer concern: every capsule declares `replayBasis` as one of `replayable`, `identity-only`, or `historical-unverified` (plan 4.7 "Replayability of historical observations"), validated by `validateSearchLossCapsule`.
7. **v1 capsule fields** — frozen as implemented in `scripts/solver-search-loss-evidence-lib.mjs`: `capsuleId, parentId, levelRevision, runId, solverRef, protocolHash, attemptIndex, stageId, eventKind, captureReason, workSpent, nodeProgress, depth, stateIdentity, pathIdentity, disposition, selection, stateSummary, context, replayBasis` — a direct implementation of plan section 4.3, with `runId`/`solverRef`/`protocolHash` as the three parts of the "run/solver/protocol identity" bullet and `stateIdentity`/`pathIdentity` each optional but not both absent.
8. **v1 event kinds** — frozen to exactly the plan's initial candidate list (plan 4.4): `budget-terminal, stage-terminal, best-progress-transition, score-width-cull, mechanic-bucket-cull, ints-bucket-cull, frontier-representative`. No producer wires any of these yet (that is Phase 3/4); the contract only validates against this closed set so a future producer cannot silently invent an eighth kind without a deliberate schema amendment.
9. **v1 selector/capture reasons** — frozen to the plan's suggested vocabulary (plan 4.5): `best-progress, late-best-progress, near-cutoff-retained, near-cutoff-culled, terminal-best, frontier-sample, progress-transition`. Confirmed the plan's explicit ban (`bad-route`, `dead-branch`, `first-loss`, `causal`) is respected: none of those strings appear in `SEARCH_LOSS_CAPTURE_REASONS`.
10. **Producer path for rich-capture Phase 4** — not chosen in this pass (Phase 4 is PR C); the plan's own preference order (existing beam research records + shared decision adapter first) is already reflected in this pass's `decisionObservationToSearchLossCapsule` adapter, which a future Phase 4 producer can call directly rather than re-deriving cull-to-capsule mapping logic.
11. **Exact run/protocol identity helpers to reuse** — frozen: `stableHash` and `isImmutableCommitSha` from `scripts/solver-experiment-contract.mjs` are reused directly (for `capsuleId`/`sha256:` identities and `run.resolvedSha` respectively) rather than re-implemented. `hashConfiguration`/`hashPopulation` remain available for a future producer to derive `run.configurationHash`/`population.populationIdentity` but are not called by the pure contract layer itself, which only validates the `sha256:` shape of whatever a producer supplies.
12. **Storage path pattern** — frozen per plan section 5.1: transient/exploratory captures are not committed; a durable, decision-bearing pilot belongs under `reports/stress/search-loss-evidence/`. Registered in `docs/solver-research-data-assets.json` as a `pattern`-kind location (no files exist yet — `status: "contract-only"`). For discovery of not-yet-durable fixtures/pilots, `tmp/search-loss-evidence` was added to `research-relations-lib.mjs`'s transient discovery roots, mirroring the existing `tmp/d1-research` convention.
13. **Consumer/query path** — frozen: `node scripts/research-asset-query.mjs --id=search-loss-evidence` for registry detail, and `buildResearchRelations(..., { discoverArtifacts: true })` / `scripts/research-relations.mjs` for lineage-joined discovery, both reused unchanged (only `research-relations-lib.mjs`'s artifact-discovery root list and its `artifactBlockPayload` field lookup were extended; no new query CLI was added, matching "reuse existing authorities").
14. **Compatibility policy: no historical backfill** — frozen per plan section 5.3: no existing artifact (D1 captures, frontier samples, operational traces) is retroactively relabeled as a `pathfinder-search-loss-capture` document. This pass adds zero real captures.
15. **Parity observable** — deferred to Phase 4 (PR C), which is the first pass that touches real solver execution; this pass has no parity surface because it wires no producer.

## Existing-resource collapse check (plan section 17)

Checked whether `scripts/solver-decision-observation-lib.mjs` alone already provides everything: it has no `capsuleId`/semantic-identity concept, no notion of `eventKind`/`captureReason`/`replayBasis`, no bounded per-selector collector with observed/retained/truncated denominators, and no run/population/protocol envelope — it observes single decisions, not a bounded sample across a whole run. `scripts/solver-research-block-lineage.mjs` supplies lineage but not capsule content. Neither collapses this resource; a thin, explicit capsule contract that *adapts* the decision-observation seam (rather than duplicating its candidate-ordering/retention semantics) is the correct shape, which is what `decisionObservationToSearchLossCapsule` does.
