# Phase 2 synthesis: orphan positives, latent parents, and the live-state anomaly

Date: 2026-09-17
Phase: 2 only

## Live-state anomaly examined

The current queue contains several bounded or replicated positives that do not earn production treatment:

- Lane A: 121/390 Class-5 residual levels have a non-trivial board-balanced width<=4 separator/interface; remaining gate is whether crossing state compresses into a small useful contract.
- Lane D1: future-intersection commitment realizability cleanly separates 18 matched exact-DEAD states from 2 exact-LIVE states on the current multi-pick population; remaining blocker is the cheapest concrete consumer plus economics and cross-parent soundness.
- Lane D2: constrained-event feasibility retains within-LIVE state signal but is not a LIVE/DEAD classifier.
- Lane D3: length-matched residual-interface substitutions commute legally at substantial frequency among accepted solutions, but the available DEAD/LIVE population does not support a direct rescue test.
- Lane F3: a cheap topology side descriptor has real tied-case signal, but its apparently sound untied subset has zero decision-relevant discordant coverage and no consumer.
- H3 length-based allocation value is positive in a bounded Card-E setting, but its authority is tied to that population and decision role.

The queue correctly says `No production treatment is earned.` Phase 2 asks why these positives repeatedly stop between observation and action.

## S2-C05 — the common bottleneck is often a missing decision contract, not a missing phenomenon

**Phase-1 origins:** M1.4/M1.6; M2.5; M3.3/M3.5/M3.6; M4 S004; M6.1/M6.2/M6.3/M6.6; M7 A3/A4/A6/A7; M9.4/M9.5/M9.8; most M10 interfaces; M12 O001/O002/O006. Frozen premises especially P013, P053, P063, P065, P122, P162, P177, P184, P189, P193, P194, P197, P200.

**Structural argument.** The orphan positives above differ technically, but each stalls at the same question form: `what decision is allowed to change, based on this observation, at what lifetime and cost?` Lane A has an interface but no proven contract state/consumer. D1 has a strong discriminator but no cheapest consumer. D3 has a legal transformation but no demonstrated DEAD rescue or in-search decision role. F3 has a predictive descriptor without a sound decision-bearing subset. These are not identical mechanisms, yet they share a missing observation-to-decision contract.

A decision contract minimally needs:

1. producer: what observation/fact is emitted;
2. identity/generalization unit: what situations it may apply to;
3. authority: observe-only, rank, retain, route, prune, revise, stop, validate;
4. lifetime/transfer radius: node, attempt, stage, solve invocation, corpus analysis;
5. consumer: which existing decision point can legally use it;
6. counterfactual: what action changes if the fact differs;
7. work semantics: what extra cost or displaced search it induces;
8. invalidation/abstention rule.

This contract is a latent parent candidate explaining a family of orphan positives without claiming a universal new runtime object.

**Competing interpretations.** (A) There is one common missing interface: typed observation-to-decision contracts. (B) The apparent commonality is administrative; each result simply lacks its own bespoke prototype. (C) The queue intentionally requires a consumer before promotion, so the repeated pattern reflects healthy gating rather than an architectural defect. These interpretations are compatible in part: healthy gating can be repeatedly exposing the same architectural omission.

**Evidence dependencies / pseudoreplication.** Phase-1 interface lenses share conceptual ancestry. The stronger evidence comes from independently produced live queue results converging on `positive phenomenon, no consumer` despite different methods: graph census, CP-SAT exact queries, native-referee splice validation, and topology descriptors.

**Temporal conditioning.** Very high for the concrete consumer because solver stages and scheduler structure can change. Lower for the abstract producer-authority-consumer-lifetime schema.

**Discriminator.** Choose two technically unrelated positives, e.g. D1 realizability and Lane A separator interfaces. For each, attempt to specify the smallest existing solver decision that could consume the signal without adding a new subsystem. If both can be expressed with the same compact contract fields and the remaining uncertainty becomes measurable economics/soundness, the latent-parent interpretation gains support. If each requires unrelated new architecture, the unification weakens.

**Smallest missing primitive.** A research-side `consumer-contract` template plus a census of current solver decision points and the input/state each already accepts. No runtime implementation is needed to test whether the interface is actually missing.

**If true.** The next fruitful research question is often not `find another phenomenon` but `can one existing decision boundary legally/economically consume this already-positive fact?` This does not itself authorize doing that work.

**If false.** Keep each positive local and do not create a cross-cutting interface abstraction.

**Confidence:** high that the pattern exists; medium-high that one contract vocabulary explains much of it; medium that it corresponds to a code-level architectural gap.

**Type:** ontology/interface issue with possible relation-only consequences. Not admitted as a canonical premise.

## S2-C06 — missing state often means missing non-puzzle decision state

**Phase-1 origins:** M1.3/M1.6; M3.3; M4 S002/S004; M7 A4/A7; M9.2/M9.4/M9.5; M10 retain->remember, remember->allocate, transfer->recognize; P148, P179, P180, P189, P194, P197, P200.

**Argument.** Several Phase-1 tensions disappear when state is expanded beyond board geometry: continuation rights, remaining work, failed attempts, uncertainty, causal commitments, provenance, artifact age, and authority. This suggests that some positive observations fail to become useful because the solver's decision representation does not retain the condition under which the observation has value.

Examples:

- D1 realizability can be useful only if its cost is compared with remaining residual work and its result can authorize a specific prune/forced-move/routing action.
- D3 commutativity depends on interface/length/mechanic context and may need a retained transformation opportunity, not merely a scalar score.
- P184 option value depends on the retained set, not candidate-local state.
- P200 makes artifact value lifetime-dependent after an action itself has been abandoned.

**Competing interpretations.** (A) The architecture lacks decision state. (B) The state exists implicitly across local objects but is not surfaced in the premise ontology. (C) The state should be recomputed on demand, so persistence would add cost and stale bias.

**Discriminator.** For a positive with no consumer, trace whether every required conditioning variable is already available at the candidate decision point. Missing variables support a state-representation gap; present-but-unused variables instead support a policy/consumer gap.

**Smallest primitive.** A decision-point state census recording, for prune/rank/retain/route/stop/revise boundaries, which of these are available: puzzle state, remaining obligations/resources, work spent/remain, predecessor identity class (not historical level identity), failure history, uncertainty, provenance, retained frontier/option-set context, artifact age, and authority.

**Decision impact.** If true, new measurements should target the missing state variable before inventing a new selector. If false, focus moves to policy consumption rather than representation.

**Confidence:** medium-high.

**Type:** candidate-new-premise or ontology/interface issue; Phase 3 must decide semantic novelty.

## S2-C07 — `positive phenomenon -> no treatment` may reflect a missing counterfactual consumer test

**Origins:** M3.5, M6, M10, P175/P192/P198 and the live queue's repeated `consumer/economics untested` dispositions.

A phenomenon study usually asks whether X exists or discriminates. A treatment study asks whether consuming X changes solves per work. Between them lies a smaller experiment: hold the solver fixed and replay the exact decision boundary under a counterfactual consumer rule. That middle primitive is often absent.

For D1, the missing test need not begin with a production exact query. A retained trace can ask how many states would invoke the test, how much downstream work occurred after those states, and what upper bound on displaced work could justify the query. For Lane A, a local exact residual query on one side of an interface was explicitly identified as the earned descendant. For ranking/retention signals, counterfactual insertion/replacement on retained candidate sets may estimate decision leverage before live implementation.

**Competing interpretations.** Existing A/B prototypes are already the cheapest honest consumer test; offline counterfactual replay may misrepresent feedback and work interactions. This is especially true for adaptive policies.

**Smallest primitive.** A `decision replay` harness over retained traces/populations that can inject a bounded hypothetical decision at one existing boundary and report eligibility, disagreement, displaced work proxy, and any correctness alarm without mutating production behavior.

**If true.** Several orphan positives become cheaper to falsify at the consumer stage, reducing pressure to build bespoke subsystems.

**If false.** Retire replay for feedback-heavy decisions and require live matched-work prototypes.

**Confidence:** medium.

**Type:** missing experimental primitive.

## S2-C08 — latent parent: information value and path-progress value are separate currencies

**Origins:** M1.6, M2.3, M7 A3, M9.4, M10 remember->allocate, P142/P185/P186/P194/P200.

Some operations are worth performing because they reduce uncertainty about which expensive action to take, even if they do not immediately extend the path. The live research program already uses this logic heavily in offline microscopes, while runtime allocation mostly remains organized around search work. The synthesis question is whether an information-valued action can ever be a first-class solver action under the same work envelope.

**Competing interpretations.** (A) Explicit information actions are needed. (B) Information is already acquired incidentally by ordinary search, so explicit probes merely tax the budget. (C) Information actions belong only to research, not cold solving.

**Discriminator.** Identify a current decision uncertainty whose resolution can be obtained cheaply from current-input state and changes a later action/dose. Compare `probe then choose` against `choose directly` under the same total work, with information production charged fully.

**Smallest primitive.** Scheduler telemetry capable of recording uncertainty before/after a probe plus the downstream action change it induced; no general controller is required.

**Decision impact.** If true, allocation semantics need to value expected downstream work avoided, not only immediate path progress. If false, information-valued operations remain research tools.

**Confidence:** medium; no runtime value established.

**Type:** genuinely plausible new premise candidate, but explicitly not admitted in Phase 2.

## False-unification guard

The live positives should not be collapsed into one mechanism. Lane A concerns structural decomposition; D1 exact future-intersection commitments; D3 path transformation; F3 topology descriptors. Their truth conditions, costs, and potential consumers differ. The commonality claimed here is only at the observation-to-decision interface and decision-state layers. A Phase-3 admission pass must preserve those distinctions.
