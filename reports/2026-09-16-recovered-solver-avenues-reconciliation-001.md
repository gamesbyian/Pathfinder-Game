## Important historical corrections

### The August full-pool categorical projection is not unfinished

The old archaeology entry describing the four-parent full-pool categorical-state projection as unfinished is stale. Later reconciliation found PR #1474 / commit `9d0f876` and the completed projection over **207 captured pools**. The tested low-cardinality categorical quota keys rescued **no exact-LIVE alternative at fixed width**. Current authorities already carry the corrected negative disposition.

This matters because the recovered "categorical completion regimes" idea must not silently reactivate quota/crowding work. H1 is a changed premise: relational event/order realizability, not another bucket key over the same captured beam pools.

### "Exact" is not the relevant legality boundary

The repository's production constraint is level-blindness and sound current-solve information, not a ban on exact reasoning in principle. Existing exact/reference labels, known solutions, historical outcomes, family identity, and offline capability memory remain illegal runtime steering inputs. A tiny exact calculation derived only from the current level/state could be production-legal if it is sound and economically worthwhile.

That distinction preserves the useful part of the recovered bounded-exact idea without turning the offline oracle stack into a hidden per-level hint system.

## Architectural descendants and their gates

### A. Obligation-first / partial-order planning

A full "schedule obligations, then realize geometry" architecture is too large for the present evidence. The repo does, however, have a clean smaller question: when exact or accepted-path evidence nominates two obligations/events, are both orders realizable, one order realizable, or neither?

That is already inside H1. A recurring order relation across unrelated parents could later earn a compact abstract-event planner. A null H1 order observer should kill this route before any schedule-first solver is built.

### B. Relational conflict learning / nogoods

Pathfinder already benefits from sound compact joint predicates when they can be stated directly, but that is not evidence that generic learned nogoods will pay for themselves. A useful conflict-learning descendant requires all of the following:

1. repeated DEAD states share a compact current-state relation;
2. the relation is sound or can be validated cheaply enough to prune/route safely;
3. it recurs across unrelated levels rather than memorizing one geometry;
4. storing/matching it is cheaper than the work it avoids;
5. any learned state is solve-local and level-blind unless a stronger generalization argument exists.

H1 is the natural source for event/order conflicts; H3 is the natural source for repair commitment conflicts. Until one of those produces a recurring relation, SAT/CDCL vocabulary adds architecture without information.

### C. Bounded exact residual inference

The March arbitrary-target `findConstrainedPath` lineage is the closest historical ancestor. It was merged and reverted almost immediately without a decision-grade behavioral test, so it is a dirty revert rather than a negative result.

The smallest useful descendant is not "run CP-SAT inside the solver." It is a bounded current-state query answering one already-earned question, for example whether a nominated event/interface is still reachable under the remaining obligations. Run it offline first on exact-labelled siblings. If it discriminates useful states, then measure runtime bounds and compare its cost against avoided `workSpent` before considering production use.

### D. Bidirectional / meet-in-the-middle search

This idea remains conceptually distinct, but it has no earned treatment boundary today. Reverse search is difficult because the forward state includes path-history-dependent legality, consumed portal/axis/interface facts, turn/intersection commitments, and exact-length/self-intersection accounting. A backward frontier that ignores those facts is not a compatible state space; a backward frontier that reproduces all of them risks becoming the same search twice.

H1 can make this idea testable. If a compact residual completion-regime/interface signature recurs and is sufficient to decide whether two partial constructions can be joined, then a small offline rendezvous experiment becomes meaningful. Without such a signature, a full bidirectional solver is architectural speculation.

### E. Macro-actions

Separate two mechanisms that the recovered thread bundled together:

- **Certified forced chains:** no real choice exists after all current transition/prune logic. Historical SolverV2 ancestry makes this plausible, but modern value requires the existing forced-chain census: chain lengths, share of canonical work, mechanics crossed, and search families paying the cost.
- **Choice-bearing corridors/event-to-event routes:** these alter branching/search policy. They belong behind H1 or another mechanism-specific premise and must be evaluated as behavior change, not as pure implementation speed.

A material forced-chain census can earn a state-certified traversal optimization without proving anything about broad macro-action search.

## Relationship to current live queue

No priority change is warranted.

1. **Card E continuation/handoff sizing remains the active premise execution gate.** It already has positive first-loss/seeded-reachability evidence and a prespecified larger-sample next step.
2. **H1 is the strongest independent acquisition premise.** It is the correct home for event feasibility, completion regimes, obligation-order questions, and any later schedule-first descendant.
3. **H2 stays an observer.** It can later earn allocation/continuation questions if structural stasis predicts low marginal value.
4. **H3 stays an observer / WS6 premise generator.** It can later earn dependency-conditioned repair if a compact commitment interface recurs.
5. **Forced-chain traversal remains conditional on a modern census.** It is a speed/work question, not a solve-acquisition priority override.
6. **Bidirectional search, generic nogood learning, broad macro-actions, and runtime exact subsolving are not independent queue items.** They are descendants with explicit evidence gates.

## Stop rules

- Do not revive August categorical quota/crowding work under the name "completion regimes."
- Do not build a schedule-first solver before H1 finds recurring order/feasibility structure.
- Do not implement generic conflict learning before a compact recurring conflict relation is observed.
- Do not put offline exact labels/known solutions into production routing.
- Do not build reverse search before a sound rendezvous/interface representation exists.
- Do not infer macro-action value from static corridor geometry; dynamic legality must certify the chain.
- Do not let these descendants displace Card E or the current WS2 priority simply because they are architecturally novel.
