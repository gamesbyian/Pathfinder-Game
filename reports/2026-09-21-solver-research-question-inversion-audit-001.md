# Solver research question inversion audit 001

> **Status:** conceptual audit complete; no automatic queue expansion.
> **Date:** 2026-09-21.
> **Source authority:** `docs/solver-research-question-relations.json` on current `main`.
> **Purpose:** invert each live/recent solver-research question to expose directional assumptions, then retain only cross-cutting question-generation lessons that are not already owned elsewhere.

## Method

A literal negation is usually scientifically empty. For each registered question, ask for the nearest useful inverse along one or more axes:

- add capability ↔ remove redundant capability;
- increase dose ↔ reclaim overexposure;
- prove DEAD ↔ certify LIVE/slack/fragility;
- compress ↔ test whether non-compressibility is itself informative;
- explain failures ↔ explain cheap successes / early determination;
- universal descriptor ↔ board-local derivation;
- recurrence/reuse ↔ cheap one-shot reasoning;
- more diversity ↔ deliberate concentration;
- global treatment ↔ safe/local islands;
- historical capability freshness ↔ capability regression/obsolescence.

An inverse is a **question-generation diagnostic**, not a sibling experiment entitlement. It enters the live queue only through the ordinary evidence and authority gates.

## Cross-cutting findings

### 1. Work subtraction is under-asked

The registry contains many questions about adding capability, dose, retention, retries or exact reasoning. Their inverses repeatedly ask whether current production work can disappear.

This is not a call for a second work-elimination program. The 2026-09-21 computational-work-elimination audit already closed generic proof-store/cache architecture and routed dynamic BC1 removable-work economics to its existing owner. PR #1952 separately measures the oracle ceiling for one-successor beam work. The durable lesson is methodological: every additive/allocation proposal should also ask whether the same evidence nominates removable or dominated work.

### 2. Proofs have useful positive complements

DEAD-oriented exact/relaxed facts often expose slack, fragility, low entropy or robust optionality on the passing side. A hard-prune null does not imply the representation has no ordering/retention/allocation value, but any softer consumer needs its own opportunity/economics gate.

### 3. Non-compressibility can be a result

Several recent lines seek compact reusable descriptors. When compression fails cleanly, the follow-up should explicitly consider whether the phenomenon is board-local, high-dimensional or one-shot enough that selective per-instance derivation is the correct architecture. Do not automatically search for another bucket vocabulary.

### 4. Success-side evidence is comparatively weak

Failure-response, first-loss and exact-DEAD machinery are now rich. The mirror question is less developed:

> On successful runs, when did current-input evidence first make later exploration avoidable or nearly deterministic?

This is an offline/oracle-ceiling question first. It must not use the eventual answer as a cold runtime feature.

### 5. Invention needs an obsolescence mirror

A changing production boundary can make old capabilities redundant. The capability-invention register correctly asks what the residual demands; periodic research should also ask which enabled capability families have lost unique marginal solve value. Removal still requires matched-work/capability protection and cannot be inferred from low aggregate participation alone.

## Durable action

Add a lightweight **question-inversion checkpoint** to the research operating model. It does not create a new registry or require every inverse to be tested. Before promoting a new question, and at closeout when choosing descendants, write the useful inverse and check whether it:

1. is already owned by an active/deferred question;
2. exposes removal/overexposure/obsolescence rather than addition;
3. turns a negative certificate into a positive slack/fragility question;
4. turns a compactness failure into a non-compressibility/per-instance hypothesis;
5. turns failure evidence into success/early-determination evidence;
6. changes the causal direction or decision seam enough to be materially distinct.

Only an inverse with a concrete evidence source, decision-changing discriminator, population and smallest next gate deserves question authority.

## Queue disposition

No new active workstream is created by this audit.

Two deferred hooks are worth preserving because they are not fully owned by current questions:

- **success-side avoidable work / early determination:** reopen when retained solved-run evidence can define a leakage-safe offline oracle for the earliest current-input decision point after which measurable downstream work is avoidable;
- **capability obsolescence / dominated production stages:** reopen after a material production-boundary change or portfolio churn when current evidence can measure unique marginal solves and removable work for existing stages/techniques.

The one-successor/forced-work prevalence probe and BC1 removable-work economics remain with their existing owners.
