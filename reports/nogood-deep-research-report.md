# Nogood Learning and Conflict Analysis in Search

Effective search algorithms often **learn from failure** by recording information about conflicts (so-called *nogoods* or clauses) rather than simply marking a whole search state as dead.  In SAT solvers this is the core of CDCL (Conflict-Driven Clause Learning), while in constraint programming (CP) variants of nogood recording and **conflict-directed backjumping (CBJ)** have been studied for decades.  The key idea is that a failure at one part of the tree may repeat in others unless we capture *why* it failed.  Abstract explanations (nogoods) generalize beyond a single state, potentially pruning more of the search, whereas exact‐state memoization (like a transposition table) only prunes that exact state.  Early CP work by Schiex and Verfaillie (1993) showed nogood recording can hugely speed up *dynamic CSPs* (where constraints change) – for example, adding a single constraint might otherwise force a full re-search, but storing nogoods can solve the new problem much faster.  In particular, *stronger propagation* (e.g. backtracking with nogood learning instead of pure forward-checking) yielded orders‐of‐magnitude speedups on hard problems.

- **What is learned.**  In abstract nogood learning, one records a *partial assignment* (or condition) that is guaranteed unsatisfiable (no solution extends it).  For example, one learns “{A=night, B=night} is unsatisfiable” rather than remembering an entire 30-variable assignment was bad.  SAT solvers learn clauses (nogoods) that explain the conflict; CP solvers can learn multi-variable constraints or record which combinations fail.  In contrast, exact-state memoization (tabulation) would only mark a specific full state as dead, which almost never recurs except in trivial cases.

- **Logical validity.**  The learned constraint (clause/nogood) must be logically implied by the original problem.  In CP, conflict learning typically builds this by tracing back constraints or propagation rules: any nogood is justified by the combination of constraints that failed.  For instance, in the cited work the solver identifies that only variables A and B ever caused the failure, so the nogood `{A=?, B=?}` is valid (every solution with those values must violate some constraint).  In SAT/CDCL, learned clauses come from resolution on the original clauses, so they are guaranteed logical consequences.  In CP+SAT hybrids (lazy clause generation), propagation is encoded as clauses that are valid globally. 

- **Scope (where it applies).**  Learned clauses in SAT or LCG are *global*: once recorded they persist and prune any branch (no need to retract as the search backtracks).  Traditional CP nogoods are often also global (once conflict identified, add it to the problem).  CBJ-style *conflict sets* are somewhat local: they guide backtracking but aren’t always stored for future reuse beyond the current search node.  The scope can also be problem-specific: some methods learn only within a subtree (local) or across restarts/revisits (global).  Bayardo & Miranker (1996) distinguish *size-bounded* vs *relevance-bounded* learning: one deletes irrelevant clauses once you leave a subsearch.  Global clauses cover many branches, whereas local ones only prune the immediate branch.

- **Recurrence likelihood.**  An abstract nogood outperforms exact memorization only if the conflict pattern recurs on different branches.  The smaller (more general) the nogood, the larger the set of branches it covers.  As the Japanese tutorial notes, a full assignment nogood will hardly ever reappear, but a minimal nogood (involving only the real culprits) can hit many future branches.  Empirically, hard or *near-threshold* CSPs yield recurring nogoods and big savings, while trivial or highly constrained problems yield none.  Conversely, if conflicts are always unique (no structural repetition), learning yields little reuse.

- **Storage and lookup.**  Nogood clauses or conflict sets must be stored (often in hash tables).  In SAT solvers, this can be millions of clauses, so they use efficient clause databases and deletion heuristics (e.g. by LBD score).  In CP, storing all subproblems explicitly can be exponential, so practical algorithms use bounded learning (see below).  Exact-state tables (transposition tables) can also be huge.  Lookup costs must be weighed: a large stash of long nogoods can slow propagation if rarely used.  The overhead of checking a large learnt clause base is one reason SAT solvers delete clauses that aren’t frequently active.  CP nogood stores similarly need management; some implementations only keep a fixed number of recent conflicts.

- **Interaction with search and propagation.**  Learning transforms the search.  By recording nogoods, the solver often *backjumps* multiple levels (skipping irrelevant choices) and prunes more aggressively.  In SAT/CDCL this is built-in: unit propagation on learned clauses adds pruning, and backjumping is directed by the 1-UIP clause.  In CP, if nogoods are integrated with propagation (as in LCG), they can trigger earlier failures (extra propagation) as soon as partial assignments match them.  The actual impact depends on variable/value ordering: a “perfect” ordering can make backjumping moot.  Empirical studies (Chen & van Beek, 2001) show that adding CBJ to a GAC solver can still give huge speedups, even though in theory strong lookahead reduces the marginal benefit.  However, other studies (Bessière & Régin 1996) concluded arc-consistency plus static order often makes CBJ redundant; the consensus is that learning helps most on harder, less-consistent problems and with weaker heuristics.

- **Empirical evidence and costs.**  Learned-constraint techniques show large gains on many benchmarks.  For example, Schiex & Verfaillie found nogood recording cut constraint checks dramatically on difficult problems.  LCG systems (e.g. G12 FD, Chuffed) consistently outperformed pure CP on many scheduling and resource problems.  Conversely, work by Krüger et al. (2022) shows that if one doesn’t delete learned clauses, CDCL performance degrades (runtime becomes long-tailed).  This highlights a key negative: **learning can hurt** if conflicts rarely recur.  When learned clauses just accumulate without useful reuse, they bloat memory and slow down propagation checks.  As one source paraphrases, “too much information” makes search worse.  Bayardo & Miranker’s theory shows even bounded learning must be managed: simple size-bounding isn’t enough, and relevance-bounded schemes are preferable.

- **Representation matters.**  A central question is *how* conflicts are expressed.  Low-level (exact state) nogoods rarely recur; richer languages that capture structure generalize better.  For instance, LCG’s approach of encoding propagations with Boolean variables and clauses lets it express disjunctive and global constraints succinctly.  Explanations that use auxiliary variables or capture global constraint semantics (e.g. Hall-interval reasoning for alldifferent) tend to produce more powerful nogoods.  Researchers look at signatures like *conflict reuse frequency* (how often a learned nogood actually fires) and *search space reduction* to decide if a given explanation language is effective.  For example, if introducing auxiliary boolean for each tuple in a table constraint allows one to learn a clause that covers many assignments, then repeated conflict pruning will increase.  In contrast, naive encodings that blow up clause size rarely help. 

- **Conflict-Directed Backjumping (CBJ).**  CBJ is a lightweight form of learning: on each dead end it records the set of variables involved in all conflicts seen along that branch (the *conflict set*).  It then backtracks to the deepest variable in that set, skipping intermediate levels.  What is learned is essentially “these vars are interdependent in this conflict”.  Validity comes from the fact that if any value had worked for those vars, the conflict wouldn’t occur.  The scope is local (it only influences where to backtrack in this search path).  It may not “store” the conflict for later branches (some variants do) but still prunes many redundant searches.  Storage is minimal (sets of indices), and lookup is just reading that set.  Empirical results (Chen & van Beek) show CBJ is very effective on many CSPs, though if your variable ordering is already ideal or you enforce strong consistency, CBJ adds little.  In practice, CBJ is often implemented with minimal overhead and yields substantially shorter backtracking sequences on tough problems.  A negative case: if conflicts involve *all* past variables (very entangled), CBJ backjumps only one level (becomes chronological).  

- **Retention policies and bounded learning.**  Because learned constraints accumulate, modern solvers enforce bounds.  SAT solvers delete clauses by heuristics (LBD, activity, age) to keep database size under control.  CP solvers likewise may discard old nogoods or limit their size.  Bayardo & Miranker contrasted two regimes: *size-bounded learning* (never record clauses above a fixed literal size) vs *relevance-bounded learning* (keep clauses only while they involve “recent” variables).  They proved relevance-bounded schemes can retain the major runtime benefits with far less memory.  Likewise, distributed CSP protocols limit nogood messages per agent to a recent window.  The guiding principle is that very large or stale nogoods, which rarely trigger, should be dropped to save space and checking cost.  No consensus on the best policy exists in general; it often depends on problem class.  But clearly if *no useful nogoods recur*, pruning them helps. 

- **Explanation overhead.**  Every learned nogood or clause must be generated, which can slow down solving.  In CP, this means instrumenting propagators to produce an explanation (a set of conditions) whenever they deduce a value elimination or conflict.  This can double the cost of propagation.  For example, naive explanation engines slowed CP solvers by a factor of ~2–10 in early LCG prototypes.  However, if the search is dramatically smaller, it pays off.  In LCG each propagation event creates a clause only when needed (lazy generation), reducing overhead.  Still, if conflicts are rare (easy subproblems), explanation work may outweigh its benefit; Schiex et al. observed that with plain forward-checking, nogood recording hardly builds information.  In other words, when propagation already solves the problem, learning adds needless cost.  

- **Negative results and limits.**  Learning is not a panacea.  In fact, experimental studies have found cases where naive learning *worsens* performance.  If every branch has a unique conflict (high variability), many learned nogoods will never match again, cluttering the store.  As Krüger et al. (2022) show, unchecked clause accumulation can skew runtimes (multimodality) and degrade median performance.  In CP, the dynamic CSP results noted no learning occurs on highly consistent (easy) problems.  Other work (Bessière & Régin, 1996) claimed that with GAC, CBJ was often pointless.  Overall, useful learning requires *repeated structure* in conflicts; its value is judged by metrics like how often a learned constraint actually prunes a branch (conflict recurrence), how much it reduces future backtracking, or how much extra propagation it induces when matched.

- **Empirical signatures of effectiveness.**  Researchers gauge a learning scheme by looking at indicators such as **conflict recurrence frequency** (how many learned clauses are reused), **reduced node revisitation** (less revisiting same states), **shorter backtracks**, **reuse of learned objects**, and **increased unit propagation**.  For example, if a learning technique cuts the average depth of backtracking dramatically, that signals success.  Schiex et al. used reduction in “consistency checks” on subsequent solves as evidence.  Others measure the rate at which learned clauses become unit and prune domains.  In practice, one would profile the solver with/without learning: if learned nogoods are rarely activated, or if they tend to have very large size, then the overhead likely outweighs the pruning gain.  Conversely, seeing the search tree shrink or faster proofs of inconsistency when reused nogoods fire indicates a productive learning language.  

- **Guidance for path solvers.**  A bespoke stateful path-search solver (on a grid with resources/topology constraints) may not easily adopt full CDCL without rewriting into SAT.  However, **lightweight learning** is still promising.  For example, the solver could implement **conflict backjumping with small nogoods**: whenever a branch fails, derive just the minimal set of conditions (like resource constraints, remaining distance, etc.) that caused the dead end, and backtrack to the most recent decision in that set.  It might also cache small “dead-end” patterns (e.g. remaining-resource<0 at some location) in a hashtable for future branch pruning, but only generalizing as much as the domain allows.  Another option is **lazy constraint generation**: at failure, introduce a new global constraint capturing the reason (e.g. “in this area with these obligations, no path exists”), if such can be formulated compactly.  In practice, evidence suggests that **reason minimization** is critical: only log the essential failure conditions, not the full state.  Retaining only a few small nogoods (bounded learning) or forgetting old ones is prudent, since a path problem may quickly accumulate many dead ends.  Ultimately, the best sign of relevance will be if a learned constraint ever actually prunes a new branch.  If the solver can collect metrics (like conflict matches or reduced backjump distance), it should do so and prune the learning if it’s not paying off.
