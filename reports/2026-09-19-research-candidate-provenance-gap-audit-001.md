## Why this audit exists

The first Bundle-E retrospective found five recent question relations with neither:

- an explicit structured `triggeredBy` relation; nor
- candidate/alternative/discriminator wording visible to the deliberately cheap machine screen.

That is a useful **provenance alarm**, but it is not itself evidence that the research system failed to generate alternatives.

This pass asks the narrower question the plan requires:

> Was the candidate set absent at decision time, or is its provenance merely absent from the current structured relation?

No new solver compute, agent-wide independent reconstruction, or new registry is justified until that distinction is made.

## Findings by question

### `WS2-CLASS123-CHEAP-HARVEST`

**Classification: structured-memory false positive.**

The closeout explicitly decomposes the residual into three candidate classes and then separates multiple already-known treatment families inside them:

- class-1 absent-menu winners under a known contention constraint;
- turn-biased repair;
- admissible-order non-default profiles;
- a distinct seven-level must-turn-biased seam;
- class-3 already-exposed capability.

It also records why only the must-turn-biased descendant survives.

The cheap machine screen missed this because the candidate structure lives in the report body rather than the sparse question relation.

No independent reconstruction is earned.

### `WS2-KNOWN-CAPABILITY-COMPLEMENTARITY`

**Classification: structured-memory false positive.**

The question was reopened by a concrete contradiction: one source alone nominated 137 rows while the prose claimed a six-source union of 65.

The resulting audit explicitly reconstructs a **six-source candidate panel**, preserves exact action identities, and explains why the correction changes Class 4 but does not reopen Classes 1-3 or Class 5.

This question was generated by an anomaly/correctness failure and evaluated across a concrete candidate set. The current question relation simply does not encode that nomination history.

No blind exploration is earned.

### `WS2-H2-STRUCTURAL-STASIS`

**Classification: structured-memory false positive.**

The result's “Why this ran” section explicitly says the cross-resource hypothesis harvest named H2 as a bounded next-in-order premise and describes the candidate dimensions in H2's own list.

The executed test chose two cheap stasis signals only after checking what already-committed artifacts could answer without new compute, and the report explicitly leaves other candidate dimensions untested rather than pretending the whole premise space is closed.

This is exactly the kind of candidate/proposal provenance the retrospective wants, but it is preserved in prose rather than the relation graph.

No blind exploration is earned.

### `WS2-MECHANIC-COMPOSITION-CAUSALITY`

**Classification: structured-memory false positive.**

The result executes a previously frozen three-stage causal design:

1. deterministic candidate/edit construction;
2. an observer manipulation check;
3. matched treatment/control comparison with a predeclared confound stop condition.

The result also records the alternative interpretation that actually wins: relocation can reduce generic navigation difficulty rather than isolate the intended mechanic-composition cause.

This is not candidate-set absence. It is a deliberately discriminating causal design whose provenance is richer than the question relation exposes.

No blind exploration is earned.

### `WS2-GENERIC-STRUCTURAL-DIVERSITY`

**Classification: historical provenance incomplete, but not a live exploration trigger.**

The retained evidence clearly places this question inside the class-5 extinction/microscope and retention line. The reconciliation report preserves the method lineage and explicitly refuses generic width/scorer/bucket proliferation after the exact microscope reproduces the already-known B1/B2 phenotype. The related first-divergence work also demonstrates a concrete mechanic-bucket-retention mechanism and explicitly says it is a known mechanism, not a new capability premise.

What the currently retained structured surfaces do **not** cleanly reconstruct is the exact original proposal set from which “generic structural diversity” was first selected.

That is a genuine historical memory gap.

It does not currently justify a clean-room or counterfactual reconstruction because:

- the question is already a **closed tested form**;
- current authorities explicitly require a materially new mechanism-specific discriminator or architectural premise rather than another generic retention/scorer treatment;
- no live queue decision depends on knowing which alternative proposals lost when this historical question was first chosen.

The missing history is therefore scientifically interesting but currently non-decision-bearing.

Do not manufacture a `triggeredBy` edge whose exact historical identity is no longer supported.

## Bundle-E consequence

The initial machine alarm was valuable, but it does not survive as a Bundle-G trigger.

The five cases resolve as:

| Classification | Count |
|---|---:|
| Candidate/nomination context preserved in prose, sparse structured relation | 4 |
| Historical genesis incompletely reconstructable, no live decision consequence | 1 |
| Evidence of current proposal-space absence | **0** |

This result matters because a naive reflexivity layer could have done the wrong thing twice:

1. mistaken sparse metadata for poor inquiry;
2. then launched independent question generation to repair a problem that was mostly retrieval/provenance.

That would be research-about-research recursion with no solver-directed payoff.

## Prospective repair

Do not broadly backfill historical relations.

For new or materially revised decision-bearing question records, preserve enough local nomination context to distinguish:

- explicit predecessor/trigger;
- candidate/proposal set considered, when one existed;
- reason the selected question/instrument survived;
- whether alternatives were absent, rejected, deferred, or simply not reconstructed.

This should be a small extension of existing question/preflight/analysis-contract semantics if a live consumer needs it, not a new proposal registry.

## Final disposition

Bundle E's first retrospective does **not** fire Bundle G.

The recent portfolio does not show:

- formal MO domination of the agenda;
- a primary ontology/representation-blocked live question;
- a structured shared-negative intersection;
- or a surviving current candidate-set absence after bounded archaeology.

The main practical result is simpler:

> current open questions are mostly waiting for evidence acquisition, while provenance of how questions were nominated is less machine-readable than the questions themselves.

That is worth repairing prospectively, but not worth building another control plane.
