## Why this pass exists

The prior three days produced strong local research semantics and instruments, but normal discovery still requires manually crossing the report index, question registry, research-asset/resource contracts, evidence-integrity index, premise-map measurement layer, capability memory, and specialist experiment artifacts. The gap is therefore operational integration, not a missing monolithic evidence schema.

This pass deliberately avoids a database/source-of-truth migration. Existing authorities remain authoritative. The new query substrate normalizes them only at read time and carries source provenance on each row.

## Implemented integration substrate

Added:

- `scripts/research-relations-lib.mjs`: read-only adapters for question relations, research assets plus audited resource semantics, measurement opportunities, evidence-integrity records, structured report status, workstream table state, opt-in experiment state, premise snapshots, and premise admissions;
- `scripts/research-relations.mjs`: compact relation discovery/query front door;
- generic join/index/independent-support primitives intended for later saved cross-program analyses, not as a replacement scientific inference engine;
- tests covering relation filtering, duplicate identity rejection, joins, and independent-unit summaries.

The design rule is **reuse existing semantics rather than reimplement them**. Comparability, admissibility, freshness, selection, and resource meaning continue to belong to their current owners.

## Reusable population construction

The Class-5 multi-pick result established a general method lesson: real production search plus one frontier draw can still miss a sparse LIVE fraction; multiple draws improve phenomenon detection, while shared parent ancestry still limits generalization.

Added:

This turns the useful part of #1843 from a Class-5-specific script into reusable population-construction infrastructure. It does **not** make multiple siblings independent confirmation.

## What was intentionally not built

- no monolithic research-evidence schema;
- no DuckDB or persistent research database;
- no generic research epoch;
- no automatic promotion/reopen verdict engine;
- no decomposition, LNS, selector, or exact-query production treatment;
- no scalar research-productivity score.

The integration layer should make scientific relationships cheaper to inspect while leaving scientific judgment and existing authority boundaries intact.
