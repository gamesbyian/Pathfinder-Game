## Question

Now that the research system is substantially more integrated, what can it learn or advance from evidence already paid for, before buying new solver execution?

## Current-state revision

The earlier idea of a broad "zero-new-solver-compute harvest" is directionally correct but architecturally too broad for the current repo.

PR #1963 added `docs/research-question-intake.md`, whose answerability ladder already says:

1. already answered;
2. existing-data analysis;
3. instrument-only;
4. bounded compute;
5. blocked/unidentifiable.

That is the right owner. A new harvest framework, registry, or queue would duplicate it.

The better move is to apply that ladder to current live questions and repair routing/state when retained evidence already decides more than the control plane admits.

## Finding 1 — one live question was falsely live

`WS2-PARITY-RESPONSE-SIGNATURE` was still `active-candidate`, but its own result says:

- the richer static parity/portal decomposition was executed;
- it did not explain the frozen discordance beyond raw portal count;
- the tested static form is closed;
- only a materially different parity mechanism from success-path/prospective seam evidence should reopen it.

That is deferred-reopen semantics, not an active acquisition gate.

This branch changes the question state to `deferred-reopen`, gives it an explicit reopen condition, and makes the workstream row say that there is no active acquisition.

This is exactly the kind of conclusion an integrated research graph should surface cheaply: no solver compute, no new experiment, just a more truthful lifecycle.

## Finding 2 — WS1 is the strongest current no-new-solver-compute opportunity

The pre-winner work oracle already establishes large perfect-hindsight headroom:

- C2: 94.74% of solved-row canonical attempt work occurred before the eventual winning attempt;
- C1: 87.58%;
- even the conservative primary-ladder view leaves 6.80% of full-C2 canonical work before winners;
- exact historical action identity is unsafe as a skip rule because held-out rare winners disappear.

The successor question is therefore not "run another solver sweep." It is:

> using only information legally available before the next action, can simple rules capture a material fraction of that retained oracle ceiling while protecting rare winning capability?

The existing preflight explicitly says to build this dataset from current production artifacts.

Therefore the first WS1 successor gate is **existing-data analysis**, not solver acquisition.

This branch makes that explicit in the canonical workstream authority so a future agent does not unnecessarily dispatch a new sweep before exhausting the retained evidence.

## Finding 3 — forced-work remains acquisition-bound despite the large retained result

The 25.33% one-successor work figure looked initially like a large removal ceiling. The later seam audit correctly tightened it:

- candidate generation and hard-prune discovery work has already been spent when post-prune forcedness becomes observable;
- 25.33% is therefore a gross forcedness reservoir, not directly removable work;
- the next discriminator is global singleton/singleton-to-singleton phase prevalence and actual post-recognition consequences.

That quantity is not reconstructable honestly from the current retained summary. The next frozen-sample rerun remains justified.

This is a useful negative result for the harvest idea: smarter retention does not license pretending an unmeasured quantity is already known.

## Finding 4 — no additional active question is honestly closable from retained evidence today

The current active set separates cleanly:

### Existing-data first

- `WS1-ACTION-SELECTION-LEGAL-SIGNAL-CAPTURE`: retained production attempts are the intended first substrate.

### New telemetry / bounded acquisition still required

- `WS2-FORCED-WORK-CAPTURE-ECONOMICS`: phase-level deterministic-chain economics;
- `WS2-PARITY-PHASE-DISTANCE` and `WS2-CHECKERBOARD-CAPACITY`: corpus opportunity/soundness evidence;
- `WS2-CUT-BALANCE-PROJECTION`: BC1 safety/economics consumer;
- `WS2-REPAIR-DEADLINE-ALLOCATION`: matched-work treatment;
- `WS2-CAPABILITY-INVENTION-DEMAND`: current-head freshness plus broader first-loss sampling;
- `WS6-DEPENDENCY-CONDITIONED-REPAIR`: independent-parent replication.

The retained evidence materially sharpens all of these, but does not decide them.

## Finding 5 — capability obsolescence stays deferred

The inversion audit correctly preserved capability obsolescence / dominated production stages as a deferred hook.

The recent portal-coarse promotion is a material boundary change, but current retained evidence is insufficient to infer safe removal of other stages. The pre-winner oracle demonstrates why: actions that look globally low-value or zero-win in development can still own rare held-out winners.

Therefore:

> promotion churn is enough to justify periodically asking the obsolescence question, but not enough to answer it from aggregate participation or winner counts.

Keep the hook deferred until current evidence can measure unique marginal solves plus removable work under capability protection.

## Finding 6 — experiment cancellation is now a first-class no-compute outcome

The recent connectivity-cut overlap preflights were cancelled after downstream-work economics made their result non-decision-bearing.

That is the strongest concrete example of the research system becoming smarter without more solver compute:

> a later result can lock a decision strongly enough that a preregistered experiment should never run.

No additional currently queued experiment was found to be similarly decision-locked during this pass.

## Method consequence

Do not add a recurring "zero-compute harvest" ceremony.

Instead, at question intake and before acquisition:

1. query retained evidence;
2. ask whether later evidence has already locked the decision;
3. classify the surviving ambiguity as existing-data, instrument-only, bounded-compute, or blocked;
4. repair stale lifecycle/queue state immediately;
5. buy solver execution only for a quantity that retained evidence cannot truthfully reconstruct.

This is already the intended research method. The improvement is to apply it aggressively.

## Immediate disposition

- parity-response static form: **deferred-reopen**;
- WS1 legal-signal capture: **existing-data first; no new solver acquisition for the first gate**;
- forced-work, BC1, parity/checkerboard, repair allocation, capability-invention freshness, and WS6 replication: retain their current earned acquisition/telemetry gates;
- capability obsolescence: remain deferred;
- no new workstream, registry, framework, or generic harvest tool is earned.
