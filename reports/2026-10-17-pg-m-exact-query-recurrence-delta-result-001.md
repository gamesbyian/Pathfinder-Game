## Exact observations and independent units

The original [September 17 PG-M Phase 0](2026-09-17-lane-c-phase0-retained-evidence-rejoin-result-001.md) already closed B/C/D on then-retained material: B's important must-pass/cross lower-bound numeric caching is shipped and measured positive, C's cheap mechanic predicates are negative controls, and D's offline exact query families did not reuse identical dependency keys. Only materially changed evidence earned a new rejoin, not an automatic Phase-1 observer.

The six current retained query result sources are enumerated with their exact SHA-256 checksums in the [permanent machine verdict](stress/pg-m-exact-query-recurrence-delta-20261017-001.json):

| Real-search frontier multi-pick | 50 | 2 | 48 DEAD, 2 LIVE |

| **Total observations, not independent samples** | **165** | **32 distinct puzzle IDs** | **143 DEAD, 22 LIVE** |

All labels are decisive: CP-SAT `INFEASIBLE` for DEAD and referee-validated accepted paths for LIVE. The program aborts on a contradictory fate for the same complete raw path and on any source-count or correctness drift. There are no UNCERTAIN cases in these sources.

Deduplicate on the **full immutable query identity**: corpus, parent level, complete raw-XY prefix. The result is:

| Identity / opportunity measure | Result |
|---|---:|
| Labelled query observations | 165 |
| Unique exact prefix queries | **162** |
| Duplicate exact-prefix alias groups | **3** |
| Identical query groups shared between source families | **0** |
| Opposite fate on identical prefix | **0** |
| Independent parent puzzle IDs | **32** |
| Puzzle IDs appearing in two or more source families | **13** |

The three duplicate aliases are historical remappings within the published topology-fork source reports, e.g. `P00075-w2-A0-B5-original` and `P00075-w5-A0-B5-alternate` record one and the same LIVE prefix. They are **not** two new derivations on an active solve trajectory, and should not inflate any repeated-fact frequency. The 13 overlapping parent IDs come mainly from newer revised-prefix and multi-pick queries against the same frozen hard boards; the actual prefixes and proof questions differ.

Critically, even a collision under this exact identity would only show repeat *offline reference calls*, not necessarily solve-local cacheable work. An efficient reuse mechanism needs a **pre-computation derivation key** that is sound for its declared fact and cheaper to check than the calculation it skips. A coarse `(level, endpoint, raw depth)` signature cannot stand in for proof identity: PG-N already found LIVE and DEAD prefixes with that same signature. Repeating the source `levelId` is even weaker evidence.

## What cannot be inferred

The fresh 75 DEAD labels, PG-K's 12 DEAD revised states and PG-D's retained LIVE/DEAD fork analyses greatly improve access to **different** exact states. They do not record whether two current search actions in one invocation redundantly computed a sound connectivity/residual blocker certificate, whether those re-derivations were expensive, or whether they occurred before the same fact's original dependency became invalid.

No source provides a common cold invocation ID, action/stage timestamp, proof consequence dependency projection or avoidable canonical work for this query. PG-D's maximal-gauntlet analysis is a *replay of already-labelled forks*, not an additional independent set of exact CP-SAT calls; do not double-count it. PG-H's read-only middle-state capture also did not buy exact labels and is not part of this exact-query population.

Thus this result **closes the original PG-M retained-exact-query recurrence rejoin on the current six-source delta**, rather than closing solve-local reasoning, source-specific blocker certificates or hypothetical typed reuse. A new generic cache would be unjustified.

## Next executable gate

Only reopen instrument work after some **current** search/revision observer (for example PG-L's canonical action/basin overlap or PG-P's commitment-descent shadow) produces a falsifiable within-one-solve claim:

1. What exact sound fact is being re-derived, with its complete dependency key or sufficient certificate?
2. In which same-invocation attempts/stages and canonical work positions does the same fact occur?
3. Can a cheaper current-state selector/check discover that fact *before* its normal derivation, without a flood-fill-equivalent lookup cost?
4. How often is that fact acted upon and how much solver work or wall cost can it actually save?

Until then, a new blackboard, generic transposition policy, cross-board reason reuse or a purported direct cold-solve advantage is not earned. The current lower-bound memo remains the correctly measured positive reuse pattern, and the broader per-instance inference premise remains conceptually open.
