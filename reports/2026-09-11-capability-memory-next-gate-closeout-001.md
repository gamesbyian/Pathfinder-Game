## What today established

The durable scientific insight is that **promotion disposition and demonstrated capability are different facts**. A policy can be correctly rejected for production while still exposing a distinct basin, and a promoted policy can improve the aggregate while displacing a smaller old basin. Pathfinder now preserves those facts without making historical level identity legal at runtime.

The implementation already provides the required substrate:

- rebuildable current-row and historical-signature capability-memory analysis;
- explicit current-vs-historical evidence semantics, censoring abstention and provenance boundaries;
- overlap, uniqueness and greedy-union diagnostics;
- protocol-compatible solved-set churn in ordinary solver-health records at zero extra solve compute;
- current workstream/future-work routing and level-blindness rules;
- temporal-anchor and displaced-capability concepts without creating a second queue or standing truth database.

No further framework is warranted before the first bounded use answers whether the residual actually contains meaningful complementary capability.

## First WS2 capability-memory census

Use the **named current production residual** as the baseline. Prefer evidence already on disk. Start with a small set of materially distinct policies/mechanisms whose provenance and disposition are already understood, for example:

- portal coarse-state merge, as a large closed-negative survivor-policy contrast;
- goal-attraction guidance-distance treatment/retry evidence, as a scorer/guidance contrast;
- repair turn-bias evidence, as a repair-search contrast;
- compact class-1 beam-policy evidence where compatible current rows exist, as a beam configuration/retention contrast;
- displaced winners from accepted gain/loss changes when protocol-compatible before/after rows are available.

These names are **candidate evidence sources, not a required permanent panel**. Omit any source whose protocol/current-row meaning is not comparable enough for the question. Historical gain lists may still be included as nominations, but never counted as confirmed current capability.

### Required outputs

For each included source, record:

1. confirmed current-residual gains when current comparable rows exist;
2. historical current-residual nominations separately;
3. unique gains/nominations and pairwise overlap;
4. work economics where the evidence supports a fair comparison;
5. mechanism family and evidence freshness;
6. any displaced current-production wins for accepted-change counterfactuals.

The key result is **not** a summed solve count. It is the structure of complementarity: whether multiple distinct policies repeatedly recover the same residual family, whether one policy owns a genuinely unique basin, and whether apparent diversity disappears after freshness/protocol reconciliation.

## Advancement rules

Advance only when the census earns one of these claims:

- **shared basin:** materially different policies recover overlapping misses or lose known-live material at the same boundary, nominating a generic representation/retention/operator premise;
- **policy-specific basin:** one policy has a reproducible unique pocket, keeping the question at WS1/technique level until a legal generic discriminator exists;
- **allocation opportunity:** rare capability is real but expensive, nominating WS2 repricing rather than a larger total budget;
- **displacement recurrence:** accepted changes repeatedly trade away the same phenotype, nominating the smallest generic counterfactual repair;
- **no material complementarity:** close the capability-memory census as low-yield and return to the existing first-priority residual program without manufacturing a new research lane.

Any descendant mechanism still owes the normal level-blind shadow/matched-work/confirmation gates. Mining many historical policies increases selection pressure; it does not reduce the confirmation burden.

## Temporal diversity

Do **not** create a standing old-solver ensemble. After a material production-boundary change, existing compatible historical rows may be used to ask whether current production is absorbing old capability or exchanging basins. Re-execute an old anchor only when:

- the old regime is behaviorally distinct and reproducible;
- existing rows cannot answer the decision-specific question;
- the expected information value justifies the compute.

A recurring old-only basin nominates a present-day generic mechanism. It never authorizes exact-level historical routing.

## Counterfactual displacement

Do **not** create a hand-maintained per-level regression ledger by default. The health timeline plus retained per-run snapshots already form the raw counterfactual bank. When an accepted change has both gains and losses, preserve the churn identity and ask whether losses recur across unrelated accepted changes.

Only if recurrence appears should a dated report cluster the displaced cases by failure/mechanism phenotype and nominate a generic premise. Isolated one-off losses remain evidence, not a work item.

## Budget discipline

Capability memory should reduce compute, not create a new expensive ritual:

- analyze the current residual only when possible;
- use existing rows/signatures first;
- reconcile union/overlap before launching reruns;
- use small bounded confirmation populations before full-corpus work;
- keep current total-work discipline unless a separate budget premise is earned;
- do not append every historically successful policy to the production ladder.

## Closeout

Today’s recommendations are therefore fully represented by three durable layers:

1. **contract/tooling:** `docs/solver-capability-memory.md` plus the analyzer and solver-health protocol/churn support;
2. **live execution:** WS2’s next gate is the bounded current-residual complementary-capability census above, with WS1/WS4/WS6/WS0 handoffs only when evidence earns them;
3. **deferred recurrence:** temporal anchors and displaced-capability recurrence remain trigger-gated, not standing compute or maintenance obligations.

Nothing else from this line needs implementation before the first bounded census is run. The next work should produce evidence, not more framework.
