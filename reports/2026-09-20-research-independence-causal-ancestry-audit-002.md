## Bottom line

The next major concept after observability + identifiability is **independence as causal ancestry**.

The recurring failure mode is:

`many observations/artifacts/reports -> treated as many independent supports`

when those objects may descend from:

- one parent family;
- one selected population;
- one source generator;
- one experiment;
- one instrument implementation;
- one analysis method;
- one ontology;
- one analyst/prompt/context;
- one critical library or model bug.

The right question is not:

> How many times did we see the result?

It is:

> Which materially relevant failure modes would have to occur independently for all of these channels to agree?

## Existing specimens

### D1: independence is already a vector

`reports/2026-09-19-research-independence-triangulation-audit-001.md` records a real disagreement:

- forensic exact relational distinction: positive;
- independent production-boundary confirmation: zero ranking disagreement.

The confirmation is strong on:

- new sample/parents;
- a different decision seam.

It is **not** independent on:

- exact/reference implementation;
- core research libraries;
- analyst/model;
- framing/context;
- ontology.

The correct synthesis preserves both channels rather than averaging them into one confidence score.

### D3: raw row count overstated independent support

The first mechanic-conditioned breakdown could be summarized as:

- 2,152/2,152 illegal candidates;
- 10 flipper-bearing levels.

The segment-level follow-up found that only **3** flipper-bearing levels produced any qualifying length-matched candidate, with one level contributing **399/567 (70%)** of the relevant candidates.

The zero remains real.

But its independent support is closer to:

> three qualifying parent boards, heavily dominated by one board

than:

> 2,152 independent confirmations across ten levels.

That is a pure causal-ancestry correction.

### Variant families

`docs/variant-level-research.md` states the same principle:

- sibling variants are correlated;
- parent families are the independent unit for generalization;
- thousands of siblings can be excellent causal evidence for one parent and terrible evidence for thousands of unrelated puzzles;
- training/tuning/confirmation must split by whole parent when parent-level generalization is claimed.

### Hint provenance

`docs/solver-evaluation-evidence.md` and provenance tooling distinguish repeated rediscoveries from independent support.

Same-regime/config repetitions and variant replay clouds must be collapsed or stratified before support volume is interpreted.

A hundred hint events may represent one causal source.

### Failure evidence

Repeated attempt/run records on one parent remain one conservative support stratum for population-level claims.

Attempt count is not parent count.

### Premise-map completeness

The premise-map hardening program found the same issue at the document/concept layer:

- multiple reports can descend from one experiment;
- multiple mining lenses can share one canonical map encoding and source corpus;
- repeated rediscovery therefore measures robustness to some framing perturbations, not automatically independent conceptual confirmation.

The blind peer-map/shadow-mining program deliberately changed construction context to obtain stronger independence.

## Independence dimensions that recur

The repo repeatedly distinguishes the following axes.

### 1. Observation-unit / cluster independence

What is the effective independent unit?

Examples:

- parent, not attempt;
- parent family, not sibling variant;
- source experiment, not descendant report;
- qualifying level, not candidate splice.

### 2. Sample / selection independence

Did the evaluation units influence candidate/question/threshold selection?

A fresh locked sample can be independent even when drawn from the same generator.

### 3. Source / construction independence

Did the evidence come from a materially different process?

A new random seed can provide sample independence without distributional independence.

### 4. Decision-seam independence

Does the second channel test the same construct at a different real consumer boundary?

D1's production-retention confirmation is valuable partly because it moves from forensic states to the actual ranking seam.

### 5. Instrument implementation independence

Do channels depend on separate observers/oracles/reference implementations?

Two workflows calling the same exact model are not implementation-independent simply because the artifacts differ.

### 6. Analysis-method independence

Do different reductions/estimators expose different failure modes, or merely reformat the same statistic?

### 7. Analyst / model independence

Was the reasoning produced independently, or by one analyst/model carrying the same assumptions forward?

Often Pathfinder correctly makes **no claim** on this axis.

### 8. Framing / context independence

Were task framing, prompts, current authority exposure and prior conclusions independent?

The premise-map blind tracks deliberately protected this axis.

### 9. Ontology / representation independence

Do channels share the same conceptual decomposition?

Multiple mining passes over one canonical map are less independent than a separately reconstructed peer ontology.

### 10. Critical-code / common-mode independence

Could one shared library/model/state encoding bug affect all channels?

This is distinct from sample independence.

## What should not be collapsed

### Level-blindness is not sample independence

Runtime legality says the solver did not use forbidden historical steering.

It does not say the evaluation sample was untouched.

### Sample independence is not distribution independence

A fresh seed from the same generator can confirm a fixed candidate without testing broad transfer.

### Distribution independence is not implementation independence

Two generators can still feed the same buggy oracle.

### Separate workflow artifacts are not independent implementations

Artifact multiplicity is not causal multiplicity.

### Independent rows are not automatically independent parents

Especially in family/attempt/candidate-splice data.

## Synchronous relationship with observability + identifiability

The three concepts should form one chain, not separate ceremonies.

### Step 1: resolution

For each evidence channel:

- is the phenomenon observable for the claim?
- does the observation discriminate the live rivals?
- is execution fidelity adequate?
- is the result actually resolution-ready?

A non-resolution-ready channel does not become strong evidence merely because an independent channel fails the same way.

### Step 2: independence

For the channels that are resolution-ready:

- what is the effective independent unit?
- which causal/common-mode failure dimensions are shared?
- which are genuinely independent?

### Step 3: synthesis

Preserve disagreement when channels answer different seams or populations.

Do not average away:

- forensic positive + production negative;
- one-parent causal certainty + weak cross-parent recurrence;
- same-source confirmation + cross-source transfer failure.

## A useful support topology

For one claim, think in terms of a small graph:

`claim <- resolution-ready evidence channels <- causal/common-mode ancestors`

Two evidence nodes add less support when they share most ancestors.

This is not a numeric Bayesian confidence engine.

It is a provenance/interpretation discipline for preventing pseudoreplication and forced consensus.

## Candidate machine primitive

A future shared vector would plausibly make the following fields explicit:

- `observationCluster`;
- `sampleSelection`;
- `sourceConstruction`;
- `decisionSeam`;
- `instrumentImplementation`;
- `analysisMethod`;
- `analystModel`;
- `framingContext`;
- `ontologyVocabulary`;
- `criticalCode`.

Each axis should state the relationship, not a score.

Examples:

- `independent`;
- `partially-shared`;
- `shared`;
- `not-claimed`;
- plus a short reason/reference.

Do **not** extract this yet merely because the vocabulary is attractive.

The existing WS2 failure-response contract has one rich `independenceVector`, but other systems currently express the same ideas in specialist prose/roles rather than a second common machine contract.

## Promotion test

A shared machine independence vector is earned when a second live decision-bearing artifact must prevent a real ambiguity such as:

- independent parents being mistaken for cross-distribution support;
- multiple artifacts being mistaken for independent implementations;
- repeated family siblings inflating confirmation strength;
- blind/context-independent replication needing to be distinguished from ordinary fresh-sample confirmation.

At that point extract canonical axes/relationship states only.

Do not create an overall independence score.

## Standing rule

**Count causal support units, not files, rows, runs or reports.**

When claiming replication or triangulation, state the dimensions on which the channels are independent and the important common-mode failure modes they still share.
