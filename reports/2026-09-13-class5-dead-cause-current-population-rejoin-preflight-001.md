## Metrics

For the primary cluster report, per level and pooled:

- rejection count and `workPoint` distribution;
- number of distinct exact-state fingerprints;
- exact-state record-sharing fraction;
- number of distinct reached-set fingerprints;
- reached-set record-sharing fraction;
- number of distinct normalized boundary-blocker sets;
- boundary-set record-sharing fraction;
- number/fraction of recurring shape groups represented by more than one exact state;
- for recurring shape groups, recurrence distance in `workPoint` so repeated shapes can be distinguished from immediate duplicate emissions;
- observer/runtime overhead if cheaply measurable, but do not turn this into a performance benchmark.

The key comparison is **structural recurrence beyond literal exact-state duplication within the same solve**.

## Advancement rule

Advance to cause reduction only if all of the following hold:

1. at least **6 of the 12** selected levels produce enough primary-cluster records to form a recurrence statistic (minimum 25 records);
2. pooled reached-set or normalized-boundary sharing exceeds pooled exact-state sharing by at least **10 percentage points**;
3. the same direction holds in a majority of the informative levels, so one huge level cannot manufacture the pooled result;
4. at least 25% of structurally recurring records belong to groups containing more than one exact-state fingerprint;
5. recurrence is not almost entirely adjacent duplicate emission: the summary must show repeated groups recurring at separated `workPoint`s.

These thresholds are deliberately much weaker than August's ~30-point structural-vs-exact gap. The question is whether a real population survives, not whether the current sample reproduces the old effect size exactly.

If the gate fails, close this connectivity-derived solve-local reuse descendant. Do not build a faster cause extractor merely because the September two-level diagnostic proved one repeated cause can exist.

## If positive: smallest next cause-reduction gate

Do **not** repeat September's expensive prefix-length bisection across a larger random beam sample first.

The native connectivity rejection already supplies a sound conclusion and a concrete reached/boundary object. On the recurring groups from this pass, ask a narrower question:

> Which subset of the normalized boundary blockers plus current reachability/resource facts is sufficient to reproduce the same native connectivity rejection across the group's distinct exact states?

Start with shadow/offline removal tests on the already-computed blocker set. A candidate reusable cause must satisfy all of:

- sound sufficiency under the current solver rules, not fingerprint equality;
- recurrence across distinct exact states within a solve;
- compactness materially below the full reached set/exact state;
- matching cost plausibly below a fresh `isConnected` call;
- meaningful repeated-work opportunity based on recurrence spacing/count.

Only after such a cause language exists should exact/reference machinery be used selectively to challenge ambiguous reductions or seek counterexamples. CP-SAT should not be the first-pass cause miner for every rejection.

## Shadow-safety requirement

Before any pruning/reuse behavior is implemented, shadow-match the proposed cause against current solves and record every would-fire state. Search specifically for:

- a stored/referee-valid completion extending a matched state;
- exact/reference evidence that a matched state is LIVE;
- mechanic/resource fields omitted from the cause but varying across matches;
- cause matches that occur before the native rejection would have fired and therefore require a stronger soundness argument.

A single confirmed LIVE counterexample closes the proposed cause language as unsound in that form.

## Economic gate

Even a sound recurring cause does not earn production reuse unless the avoided work is material.

Measure, for shadow matches:

- number of native connectivity checks potentially avoided;
- canonical work between repeated equivalent causes;
- downstream search work avoided if the cause could soundly fire earlier;
- cause-key construction/matching work;
- concentration by level and search family.

The intended treatment is solve-local and ephemeral. Nothing here licenses cross-level learned clauses, persistent caches, CDCL/LCG machinery, or generic clause learning.

## Stop/advance map

- **Population-survival null:** close connectivity-derived reason reuse; advance to homotopy/topological completion observer.
- **Recurrence positive, no compact sound reduction:** close reason-reuse descendant; structural fingerprint remains diagnostic only.
- **Sound compact reduction, poor economics:** preserve as observer/capability evidence; no treatment.
- **Sound + recurring + economic:** freeze a shadow-only reason-reuse pilot before any pruning A/B.

This ordering keeps the next compute small and makes every later implementation conditional on information that the previous stage actually supplied.
