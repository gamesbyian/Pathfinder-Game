## What was checked

The session taxonomy nominated these families:

- exact/reference disagreement × failure phenotype;
- failure phenotype × static descriptors;
- failure phenotype × variants;
- capability memory × current residual;
- generation/source lineage × failure phenotype;
- hint provenance × failure response;
- work-dose response × participation/exposure.

The audit asks three separate questions for each:

1. does a canonical join key already exist?
2. does executable/queryable machinery already exist?
3. does current eligible data support the intended inference?

A “no” at #3 is not a reason to write more join code.

## Why current compact evidence is insufficient

The committed standard compact-response bundle inspected in this pass contains exactly one row: R00044 from the admissible-order execution-family canary.

It has excellent identity/integrity for its actual purpose:

- one expected/observed parent;
- known protocol hash;
- immutable solver ref;
- complete population coverage;
- exact 219,802,423-node default admissible-order solve.

But its denominator is **one deliberately selected known-positive mechanism case**.

It therefore cannot support:

- prevalence;
- clustering;
- descriptor association;
- source/generator contrast;
- failure-basin recurrence;
- variant-family generalization.

Joining more columns onto that row would increase data width, not evidence.

## Joins already implemented enough

### Capability memory × current residual

This is already a named relationship in the data-asset registry and has been used in residual-atlas/capability-memory census work.

The open research need is not another join implementation. It is current fresh capability evidence or a newly motivated mechanism contrast.

### Hint provenance / discovery process × failure response

The 2026-09-19 cross-pollination program already implemented:

- query-dependent applicability;
- run-linked discovery-process evidence;
- exact-path binding;
- pre-success failed-attempt history;
- strict process join under parent + protocol/configuration + immutable solver identity;
- selection/harvest denominators.

A new “hint × failure” mega-join would duplicate this.

### Failure response × static descriptors / variants

Both are already explicit research-asset relationships with useful caveats:

- static association is development evidence and must preserve selected residual/generator confounds;
- variant siblings are dependent and parent family is the cross-family independent unit.

The missing input is a compatible broad compact-response population, not a relationship schema.

## Newly clarified join order

When the first eligible compact-response population arrives, the cheapest information-value order should be:

1. validate denominator/protocol/solver/population integrity;
2. identity/novelty/saturation as already queued;
3. static descriptor + generation/source stratification;
4. variant-family contrast where present;
5. success-process/hint controls where comparable;
6. only then buy exact/reference or rich search-loss annotation for the residual ambiguity.

This order is now recorded in `docs/solver-future-work.md`.

The point is not that every future dataset must execute every join. The order prevents expensive instrumentation from being commissioned before already-owned metadata can explain or localize the signal.

## Exact/reference join boundary

“Exact/reference disagreement × failure phenotype” is especially easy to overstate.

A legitimate join requires:

- same parent/state/candidate/query identity, not merely same level;
- reference support for the queried mechanics;
- explicit abstention/UNKNOWN handling;
- known producer/protocol relation to the failure observation;
- parent/dependence accounting.

Existing exact labels from D1, Lane A, F3, etc. are specialist query populations. They must not be smeared across level IDs onto unrelated compact failure records and called explanatory truth.

## Generation/source lineage

This join does **not** need a new registry object.

Stress corpora already preserve construction/generation provenance and selection-history caveats. Once compatible failure rows exist, joining by current level identity and stratifying by generation/source is ordinary evidence composition.

This is a useful negative result from the abstraction audit: the knowledge is scattered across two assets, but the missing thing is **data opportunity**, not another semantic owner.

## Stop condition

Do not add another latent-join framework until a real population exposes a repeated join operation whose identity/support/dependence rules are being reimplemented in multiple consumers.

The current system already owns enough join vocabulary. The next gain comes from feeding it eligible observations.
