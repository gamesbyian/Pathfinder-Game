## Distinct mechanism, not another fixed-width sweep

The previous source-matched fixed 512-wide treatment failed all three 250k development cells, and the `objectiveFirst` R03031 instance **naturally exhausted at work 209,739**. That closes narrowing from the first move in these three cases. But [the original 5000-wide frontier evidence](stress/pg-i-winning-corridor-frontier-locus-20261018.json) showed that all three *later proven* 10M winning path prefixes were actually retained through early checkpoints below 250k. For R03031 `objectiveFirst` original work at phase depth16 was only 23,568, leaving >226k strict native work for later exploration if subsequent breadth were selectively reduced. For R02108 `intersectionHarvest`, phase16 already cost ~207,493, suggesting a depth8 taper (earlier checkpoint) is the relevant counterexample. No winner path is used for scoring or retention, and the source-selected gate/technique means this cannot directly justify a product policy.

**Only three schedules, fixed now**: original unpaused width5000, width5000 until actual complete beam phase **8** then width512, and width5000 until actual complete beam phase **16** then width512. All candidates share the original source scoring profile, matching original mechanic-bucket-retention setting, exact same source gate and full underlying solver. The algorithm is not restarted at the taper: `beamSearchFromGate` consumes its own immutable-identity `BeamContinuation` from `pauseAfterPhases`, with the SAME `PrepLevel`, native state pool, meter, node counters, and source board. The next full phase sees the entire retained pre-taper frontier and only *after expanding it* trims its successor pool to 512. This intentionally differs from width512 since depth0.

## Hard guards and economical stop

- Freeze exactly the 3 existing source 10M-valid method cells (2 independent parent IDs), no new winner lookup. Prior winners are used **only after a source run pauses** for diagnostic exact prefix-presence and rank in the original cold frontier; never influence pause depth, beam width, scoring, gate or solver runtime.
- One fresh `prepLevel` per arm, `_workCap=250000`, `_atomicStrictWorkCap=250000`, `nodeBudget=250000`, `timeBudgetMs=600000`. Strict work cap refuses *before* any 12-unit or 1-unit primitive charge. A refused primitive is censored and not a failed oracle result; node count is recorded `null` on thrown strict refusal, not zero.
- Record actual pre-taper depth and work and original frontier size, original winner-prefix status/rank as a **post-hoc witness label only**, final native work, stop reason, deepest resumed phase reached if captured, referee validity, any path, and errors. Reference winners remain outside every `beamSearchFromGate` call.
- Prespecified advancement: **at least one** new referee-valid 250k isolated path not in the original width5000 source control, or a meaningful causal depth/frontier-reach signal that can motivate a different *current-state*-driven adaptive-width selector, earns further cheap study; otherwise close these fixed 8/16 taper schedules without running a width×checkpoint sweep.
- This is NOT a production-ladder A/B. Before any promotion, translate a successful mechanism to an outcome-blind, source-independent gate/profile/phase rule and run separate fixed-total-budget product and source-frozen confirmation, tracking gains and losses per parent.

The supporting workflow is a short-lived source-native diagnostic and must be removed after source-hashed artifact retention. Merely reaching a later phase or lowering work usage, without independent solving benefit, is not a production gain.
