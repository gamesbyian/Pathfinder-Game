## Why C1 can be zero-search

C0 already paid for exact whole-prefix LIVE/DEAD labels on every frozen query. C1 changes only the representation used to group those same prefixes. The label target is unchanged.

Therefore C1 does not need another exact/reference campaign. It can join:

- the frozen 581 case identities/cut cells;
- the already-produced exact labels;
- the raw current level definition needed to distinguish portal jumps from cardinal moves;
- the frozen prefix itself.

No new outcome is generated by constructing the C1 signature.

## Frozen population

Exactly the C0 population:

- 581 frozen `(cut, prefix)` cases;
- 144 C0 geometric-cut groups;
- 98 parent levels among collision-eligible groups;
- 546 existing decisive exact labels and 35 existing abstentions in the C0 result;
- no new frontier sampling, resampling, parent selection or label recovery.

The 35 C0 timeout/abstain rows remain abstentions. C1 must not rerun them merely to improve support after seeing the new grouping.

## Frozen C1 signature

C1 starts with C0's `levelId + sorted cutCells` and adds a bounded local state for every cut cell.

For each cut cell, record:

- cell coordinate;
- whether the frozen prefix uses it;
- every local visit as an `(entry, exit)` pair;
- entry/exit token from `N`, `S`, `E`, `W`, `portal`, `start`, `end`;
- whether any local incident transition is a portal transition.

Visit tuples are sorted within a cut cell. Global temporal ordering of different cut crossings is deliberately discarded.

Portal transitions are identified from the level's actual portal map **before** cardinal geometry. This matters because a valid portal pair may occupy geometrically adjacent cells; adjacency alone cannot classify a transition soundly.

### Deliberate omissions

C1 does not include:

- full prefix identity or history;
- global ordering of separator crossings;
- exact length/intersection used or remaining;
- outstanding global obligation accounting;
- mutable filter/flipper/portal state beyond whether the local boundary transition itself is a portal jump;
- F3/topological history tokens.

Those belong to later C2-C4 layers. Adding them now would convert a nested falsifier into feature shopping.

## Frozen implementation

`scripts/stress/lane-a-boundary-kinematics-lib.mjs` owns the C1 representation.

`scripts/stress/lane-a-c1-boundary-kinematics-analysis.mjs` joins existing exact-label rows to the frozen case set and corpus, derives C1 signatures, and passes decisive rows through the shared signature-collision reducer.

The helper has a regression case with **adjacent portal endpoints** to prove portal classification comes from the level portal map rather than Manhattan geometry.

## Support and compactness gate

Near-unique signatures are not success.

Call C1 **repetition-supported** only when both are true:

1. at least **20% of decisive rows** remain in C1 signatures containing two or more rows; and
2. at least **10 independent parent levels** contribute to a multi-member C1 signature.

These thresholds are frozen before C1 outcome inspection. They are intentionally coarse. They ask whether C1 still compresses a meaningful slice of the already-large C0 population rather than rewarding purity created by almost identifying each prefix.

Also report signature byte-size distribution, boundary-visit count and prefix-length distribution as compression diagnostics. Byte count is a proxy only, not the scientific decision rule.

## Fixed decision rule

### A. Mixed + repetition-supported

If one or more C1 signatures still contain both LIVE and DEAD while the support gate passes:

- C1 is insufficient;
- report how many independent parents contain mixed groups;
- proceed to precommit C2 global accounting on the same frozen population;
- do not alter C1 to repair the observed collision.

A mixed group in one parent is still a sound counterexample to C1 sufficiency; recurrence across multiple parents strengthens scope but is not required for the logical falsifier.

### B. Pure + repetition-supported

If C1 has zero mixed groups and the support gate passes:

- classify C1 as a bounded-positive representation candidate;
- do not open a production decomposition consumer yet;
- require one independent confirmation/challenge population before using C1 purity as more than development evidence.

### C. Repetition support fails

Stop the nested contract as **representation-explosive at C1**, regardless of whether the remaining groups are pure.

This is a monotonic stop. C2-C4 only add fields to C1. Added fields can split a mixed signature, but they cannot merge C1 signatures or restore repetition lost at C1. Continuing after C1 becomes near-unique would therefore only make the compression claim worse.

### D. Blocked

Any population mismatch, unresolved frozen-case join, invalid prefix transition, or correctness/input alarm blocks the verdict rather than counting as mixed/pure/negative.

## What C1 can earn

A repetition-supported pure C1 earns only independent confirmation of the compact interface representation.

It does not earn:

- region DP;
- AND/OR decomposition;
- a generic separator engine;
- production exact solving;
- a topology subsystem;
- cold routing from historical labels.

If confirmation later succeeds, the next consumer remains the smallest local interface-feasibility use with matched-work economics.

## Outcome blindness

This report, the signature helper, its tests and the reducer were committed before C1 collision outcomes were inspected. The two known C0 mixed-parent examples were used only to understand the type of boundary information C0 omitted; their LIVE/DEAD assignment was not used to select C1 fields.
