## Earned solve-research handoff: consumer-contract falsifier

### Question

Do technically unrelated bounded positives repeatedly fail to convert because the current solver lacks a usable observation-to-decision contract, or is that apparent commonality just healthy gating / unrelated local prototype gaps?

### Why this is earned

The current live authority independently contains:

- Lane A separator/decomposition: bounded positive, next question is interface-contract state size;
- Lane D1 future-intersection realizability: replicated positive, consumer/economics untested;
- Lane F3 topology side descriptor: qualified positive, no consumer proposed.

Phase 2 found the same producer -> authority -> lifetime -> consumer -> counterfactual -> economics seam across these technically different results. Existing P193/P197/P198/P200 already contain the semantic pieces, so the next move is to *test the proposed integration*, not add another premise.

### Cheapest falsifier: read-only decision-point / consumer census

Use current architecture plus retained result artifacts. Do not run new solver sweeps and do not add runtime state.

For each of Lane A, D1, and F3 record:

1. exact producer and emitted fact/signal;
2. legal information authority (observer, rank, retain, route, revise, prune, stop, proof);
3. identity/generalization unit and population;
4. lifetime / transfer radius required for usefulness;
5. smallest existing decision point that could consume it;
6. state fields already available at that point;
7. state fields missing but required;
8. explicit counterfactual action if the fact changes;
9. abstention/invalidation condition;
10. producer cost if known, plus an upper bound on displaced work the consumer could plausibly save;
11. whether offline replay is faithful enough for the decision or live feedback makes replay invalid.

### Pass / fail / split rules

**Cross-cutting hypothesis passes its cheapest gate** only if at least two technically unrelated positives can be mapped to existing decision boundaries using the same contract fields, with no new subsystem required, and the remaining uncertainty reduces to a concrete soundness/participation/economics question.

**Cross-cutting hypothesis fails** if each positive needs a materially unrelated new architecture, state model, or consumer such that the shared contract vocabulary has no decision value beyond documentation. Retire the common-interface interpretation and return each positive to local ownership.

**Split outcome** if a shared contract is useful descriptively but only one positive has an economical existing consumer. In that case advance only that local positive and do not generalize the architecture claim.

### First local descendant if the census passes: D1 consumer falsifier

D1 is the cleanest place to test the middle step because future-intersection realizability already has replicated exact-labelled separation and the live queue explicitly says `consumer/economics untested`.

Before any production exact query:

- identify the smallest existing decision boundary at which a realizability result could change retain/rank/revise/prune behavior;
- on retained evidence, estimate opportunity count, consumer disagreement rate, downstream work exposed after the decision, and producer/query cost;
- state the authority needed for the proposed action. A prune/forced-move consumer requires soundness; a rank/retain consumer does not inherit prune authority merely from exact-labelled correlation;
- if retained replay cannot model feedback faithfully, stop and specify the smallest live matched-work prototype rather than pretending replay is causal evidence.

Stop before implementation if opportunity N is negligible, no existing consumer changes action, production cost already exceeds a generous displaced-work bound, required state is unavailable without a new subsystem, or the intended consumer needs authority the current evidence does not provide.

A positive offline consumer falsifier still does **not** earn production. It earns, at most, a separately authorized matched-work live prototype with P201/P202/P204/P206 evidence rules applied.
