# Search-loss evidence: Phase 3 compact failure-response layer (PR B, scoped)

> **Status:** concluded-positive
> **Last evidence:** 2026-09-18 — full read of `.github/workflows/solver-stress-refresh.yml`, `.github/workflows/technique-census.yml`, every workflow declaring an experiment-contract `sideEffects` block or invoking `publish-solver-sweep-result.mjs`, `scripts/publish-solver-sweep-result.mjs`, `scripts/combine-technique-census-shards.mjs`, `scripts/combine-solver-sweep-reports.mjs`, `scripts/solver-experiment-contract.mjs`, `.github/workflows/harvest-solver-evidence.yml`, and `scripts/persist-decision-bearing-experiment-evidence.mjs`, current HEAD.
> **Decision:** implement the plan's Phase 3 ("shared compact failure-response projection") as a reusable library plus a mechanical per-workflow disposition contract, and wire it end-to-end for the two producers the plan itself prioritizes first (technique census, production refresh). Every other solver-running workflow gets an explicit, reasoned `specialized-opt-out` or `unsupported` disposition rather than silence, per the plan's own stop-condition discipline.
> **Remaining gate:** none blocking; genuinely remaining Phase 3 sub-programs (progress-over-work pilot, reason-seam audit, beam flow summary, replayability flags) are each their own scoped investigation per the plan and are explicitly NOT attempted in this pass — see "What did not ship" below.
> **Evidence role:** implementation record, not an experiment. No solver run, GHA dispatch, or research question is touched. This is infrastructure that changes what future runs preserve/publish, not a scientific claim about the solver.
> **Population identity:** not applicable (implementation record).

## Why this ran

The user extended `docs/solver-search-loss-evidence-implementation-plan.md`'s scope with an explicit new requirement: standard compact failure information must become automatic-by-construction across supported solver-running workflows, the same way hint/provenance capture already is -- no `--collect-failure-telemetry` flag, no custom staging/combine/harvest step an agent has to remember. This session's own PR A (Phase 1+2, merged as #1894) built the search-loss-evidence *capsule* contract (layers 2/3 of the plan's architecture) but deliberately left layer 1 (the compact failure-response projection, Phase 3) and its GHA transport untouched. This pass implements that layer.

## Producer contract audit (plan Phase 3, "Producer contract audit")

Two research passes (full reads, not greps) of every solver-running workflow and its result/combine/publish code found:

- **Per-attempt fields already computed today**, unlabeled as a "compact failure response": `portfolio-solve-sweep-lib.mjs`'s `attemptRecord`/`buildRow` (used by `solver-stress-refresh.yml` and benchmark tooling) already carries `stageId`, `outcome`, `error`, `bestBadness`, `finalBadness`, `allocatedWorkCeiling`, `allocatedNodeCeiling`, `workSpent`, `nodesExpanded`, `deadlineTruncated`, `hadAttemptError`, `refereeValid`, `attemptCount`. Technique-census cell rows already carry `status` (`node-budget-reached | work-budget-reached | exhausted | referee-invalid | error | deadline-truncated`), `nodesExpanded`, `workSpent`, `workBudget`, `techniqueKeys`.
- **Both combiners already retain every row, including failed ones, in full**: `combine-solver-sweep-reports.mjs` concatenates `levels[]` verbatim (no filtering by `ok`/`status`) and already calls `buildPopulationIntegrity`, publishing its `outcomes` taxonomy at the top level. `combine-technique-census-shards.mjs` keeps the full `results` array in `combined-cells.json` and already computes ad hoc per-tier `nodeBudgetReached`/`exhausted`/`refereeInvalid`/`error`/`workBudgetReached`/`deadlineTruncated` counters for its own markdown tables.
- **What was actually missing**: a single, standard, cross-producer field vocabulary and a *labeled*, discoverable summary object in the published manifest -- plus an honest `sideEffects.telemetry` declaration. Every one of the 11 workflows that declares an explicit `sideEffects` block declared `telemetry: 'none'`, including technique-census, which was already computing most of the relevant counters internally without ever calling that a "telemetry" side effect.
- **`classifyRow`'s existing taxonomy** (`solver-experiment-contract.mjs`) does not separately surface `referee-invalid` (it falls into `unknown`); the new compact-response layer adds this as an explicit orthogonal flag rather than editing `classifyRow` itself, since that function is depended on broadly and changing its bucket enum was unnecessary risk for this pass.
- Solved-run controls, progress/rejection/flow summaries, typed recurrence identity, handoff context, and replayability are each explicitly **not** addressed by this pass (see "What did not ship").

## What shipped

**Shared library** (`scripts/solver-failure-response-lib.mjs` + node-test): `compactFailureResponseRow(row)` projects any producer-native row into the standard field set (`identity, actionKey, outcome, refereeInvalid, nodeCeiling, nodesExpanded, workCeiling, workSpent, bestBadness, finalBadness, deadlineTruncated, error, solvedWithFailedAttempt, attemptCount`), never synthesizing a false/zero for a field the row does not report. `summarizeFailureResponse(rows, {populationIntegrity})` aggregates via `buildPopulationIntegrity`/`classifyRow` (reused, not reinvented) and reports `refereeInvalid`, `solvedParentsWithFailedAttempts` (so a failed attempt inside an eventually-solved parent stays visible), work/node/badness participation, and `coverageComplete` -- which is `null` (unknown), never a false `true`, when the population wasn't externally verified.

**Standard producer command** (`scripts/summarize-solver-failure-response.mjs`): the one CLI both wired workflows call. Reads already-combined result files, concatenates rows, writes the summary. This existing-file text (`summarize-solver-failure-response.mjs`) is also the disposition checker's mechanical "does this workflow actually transport the standard layer" signal.

**Publisher extension** (`scripts/publish-solver-sweep-result.mjs`): every manifest now carries `failureEvidence: { schemaVersion, disposition, compactPresent, sourceArtifact, summary, richCapturePresent }`. `disposition` reuses the existing `sideEffects.telemetry` declaration (no new vocabulary). `richCapturePresent` generically scans already-published `--include=` entries for `kind: 'pathfinder-search-loss-capture'` (this session's PR A), so a future Phase 4 rich-capsule producer is detected automatically with zero additional publisher wiring.

**Disposition contract** (`docs/solver-failure-evidence-disposition.json` + `scripts/solver-failure-evidence-disposition-lib.mjs` + `scripts/check-failure-evidence-disposition.mjs`, wired into `check:validators`): every one of the 16 solver-running workflows (any workflow declaring a `sideEffects` block or invoking `write-solver-experiment-contract.mjs`/`publish-solver-sweep-result.mjs`) has a machine-readable `standard | specialized-opt-out | unsupported` disposition. The checker is open-set: a *new* solver-running workflow with no entry fails validation immediately, and it catches drift in both directions -- a `standard` entry whose workflow doesn't actually invoke the shared summarizer, a stale `telemetry: 'none'` on a `standard` entry, and an opt-out/unsupported entry whose workflow has already started transporting the layer (should be relabeled `standard`).

**Two producers wired end-to-end** (technique census and production refresh, the plan's own first-priority pair):
- `technique-census.yml`: after `combine-technique-census-shards.mjs` produces `combined-cells.json`, a new step runs `summarize-solver-failure-response.mjs --rows-key=results`, passes `--failure-response-file=` to the existing `publish-solver-sweep-result.mjs` call, and its inline experiment contract's `sideEffects.telemetry` changes from `'none'` to `'compact'`.
- `solver-stress-refresh.yml`: after both corpora are combined via `combine-solver-sweep-reports.mjs`, a new `if: always()` step runs the same summarizer over both `solver-corpus{1,2}-latest.json` files with `--rows-key=levels`, then `--failure-response-file=` is added to its existing publish call. This workflow declares no experiment contract at all today (a separate, larger gap -- see "What did not ship"), so its disposition is "standard" on the strength of actually transporting the layer, independent of the (currently absent) `sideEffects.telemetry` literal.

Both wirings are pure downstream re-aggregation of rows the combiners already produce -- no solver hot-path code was touched, so there is no OFF/ON parity surface to validate here (nothing about solve outcome, ordering, work accounting, seeds, retention, or cache lifetime can change).

## Harvester integration: already implemented via an existing generic mechanism

Per the plan's own "reuse existing authorities" principle, this pass **adds no new harvester code**. Verified directly (not assumed):

- `scripts/persist-decision-bearing-experiment-evidence.mjs`'s `findDecisionBearingManifests` gates purely on `manifest.kind === 'pathfinder-solver-experiment-result' && manifest.schemaVersion === 3 && manifest.decisionBearing === true`, then `copyEvidenceFile` copies `manifest.json` **byte-for-byte** into the durable bundle. Any field added to the manifest -- including the new `failureEvidence` block -- is therefore already durably preserved automatically whenever a run is decision-bearing, with zero additional wiring. Confirmed via `persist-decision-bearing-experiment-evidence.mjs --self-test`, unaffected by this change (its fixture manifest predates `failureEvidence` and still passes).
- `.github/workflows/harvest-solver-evidence.yml`'s `workflow_run` trigger list already names both `Solver stress-corpus refresh (level-blind capability)` and `Technique capability census (isolated single-/paired-/flag-technique, full budget)` verbatim (matched against each workflow's own `name:`), so the harvester already fires after every run of both newly-wired producers.
- This gives the three retention classes for free, exactly as specified: **(1) routine compact telemetry** lives in the `solver-sweep-result`/`technique-census-combined`/`solver-stress-refresh-combined` GHA artifacts (90-day retention) and simply expires if the run is never decision-bearing; **(2) exploratory rich capsules** remain untouched by this pass (no producer emits `pathfinder-search-loss-capture` yet -- `richCapturePresent` exists precisely so a future one is picked up for free); **(3) decision-bearing evidence** is promoted verbatim by the existing gate the moment a workflow also declares a decision-bearing `researchOutcome`, which ordinary sweeps do not do by default -- matching the plan's requirement that population-prevalence-shaped promotion stay the deliberate exception, not the default.

No mutable global per-level failure database was created or would be needed for any of this.

## What did not ship (explicitly deferred)

- **The other 14 solver-running workflows' migration** to `disposition: "standard"` -- each is registered today with a specific, honest `specialized-opt-out` (not yet migrated) or `unsupported` (not a node/work-budget search-attempt producer, e.g. the three CP-SAT exact/reference workflows and the PR-triggered integrity guard) reason in `docs/solver-failure-evidence-disposition.json`. Migrating each is now a small, independently reviewable, mechanically-checked follow-up per workflow.
- **`solver-stress-refresh.yml`'s own experiment-contract declaration.** It has none today (`sideEffects` defaults to `'unknown'`, so it can never be `decisionBearing`), which is a materially larger, separate gap (every required contract field -- population/execution/limits -- would need sourcing) than adding the compact-response transport this pass did add. Left as documented remaining work rather than risking an incomplete/incorrect contract under limited scope.
- **Progress-over-work pilot, reason-seam audit, beam flow summary, replayability flags** (plan Phase 3 sub-sections): each is explicitly scoped in the plan as its own instrumentation-overhead investigation "before making universal." None was attempted here; the capsule contract from PR A already reserves fields for a future producer to populate them without a schema change.
- **`classifyRow`'s bucket enum** was deliberately left unmodified (see audit above); `refereeInvalid` is an additive orthogonal flag on the new compact-row projection instead.
- **Rich search-loss capsule production** (plan Phase 4/5) remains fully unstarted; this pass only ensures it will be detected automatically once it exists.
