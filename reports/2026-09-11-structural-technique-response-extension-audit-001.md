# Structural properties x technique response: extension audit 001

> **Status:** active existing-data extension / execution-ready
> **Evidence role:** synthesis plus reusable offline analysis; no new solver dispatch
> **Current priority relationship:** supports WS1 and the class-4/class-5 frontier work; does not displace the current observer-only joint-obligation propagation gate
> **Question:** where can already-successful structural/capability methods be extended into technique-response research without buying broad new compute?

## Bottom line

The repository already has strong evidence for generic structural difficulty and several real pairwise technique niches. The highest-value extension is not more static descriptors. It is to make the existing pairwise niche evidence pass through the same temporal, nuisance-control, family, solution-space and operational-mechanism filters that other solver research now uses.

Use this evidence ladder:

1. **temporal niche stability** across the two committed censuses;
2. **difficulty-stratified relative advantage** so generic hardness is less able to masquerade as technique affinity;
3. **existing variant-family boundary flips** for stable associations;
4. **source-controlled solution-space mediators** for the same nominated contrasts;
5. **matched operational first-divergence / all-known-basin extinction** only after the earlier stages leave a recurring unexplained mechanism.

Each stage earns the next. Do not launch a new bulk census, bulk variant campaign, generic topology expansion or black-box scheduler model for this program.

## What is already established

### Generic structural burden is real and temporally robust

The refreshed no-T1 comparison preserved the earlier broad anatomy: `constrainedObjects`, `turnConstraintLoad`, `constrainedObjectDensity`, `requiredPathLength`, `portals`, `requiredPathCoverageRatio`, `mustTurn`, `surround`, and `blocks` all retain material unsupported-risk association. Production failure has a related but non-identical ranking, so isolated repertoire difficulty and production-orchestration difficulty must remain separate outcomes.

This burden signal is useful here primarily as a **nuisance baseline**. A technique niche is more informative when it survives among levels of comparable generic burden.

### Some pairwise structural niches survived a solver refresh

The existing Gate-0F conclusion delta already establishes several temporal facts without another run:

- objective-first and intersection-harvest 5K **plain vs mechanic-bucket retention** preserve the portal-direction effect across the September-1 and September-3 censuses;
- intersection-harvest plain-vs-buckets also preserves the required-intersection direction, with the effect stronger in the refresh;
- the **objective-first 2K vs 5K width inversion persists but its old structural explanation does not**: the older scale/navigable-area story was replaced by turn-constraint/coverage/density effects in the refresh;
- beam CW-vs-CCW remains a large outcome-disagreement population with weak coarse structural separation;
- DFS CW-vs-CCW retains structural separation, but the leading feature identity changed materially.

These are exactly the distinctions a temporal niche analyzer should expose systematically: stable association, persistent outcome inversion with unstable explanation, and structurally opaque disagreement.

### Richer generic topology has already failed its current value test

The later 18-feature topology/placement bundle added effectively no held-out value beyond the coarse baseline for production failure or no-T1 status, and worsened the CP-SAT-rescue model. Therefore this program should not respond to unexplained technique response by manufacturing another broad descriptor bundle. Add a new static descriptor only when a solution/profile/trace/family mechanism nominates it.

### Capability multiplicity is a strong offline reliability signal

Isolated `solverCount` strongly predicts production success and has already shown temporal/budget-edge robustness. Use multiplicity to stratify or qualify offline evidence where useful, especially rare/singleton technique claims. Do **not** use historical per-level multiplicity as a cold production steering lookup.

## New reusable analysis added with this report

### 1. Temporal structural-niche stability

Run:

```bash
node scripts/analyze-technique-niche-stability.mjs
```

Inputs are the frozen eight pairwise relative-advantage summaries from the September-1 and September-3 census snapshots. The helper normalizes pre-cleanup action identities, compares disagreement population and top effects, and marks a feature **persistent** when it remains in the stored top-eight effects with the same direction and at least the configured material standardized-difference threshold in both snapshots.

Outputs by default:

- `reports/stress/technique-niches/2026-09-03/relative-advantage-temporal-stability.json`
- `reports/stress/technique-niches/2026-09-03/relative-advantage-temporal-stability.md`

Important censoring rule: each source summary stores only its top eight effects. A feature absent from one top-eight list is not proven absent; decision-bearing missing-feature questions should be recomputed from the base capability artifacts.

### 2. Difficulty-stratified relative advantage

Run:

```bash
node scripts/analyze-difficulty-stratified-relative-advantage.mjs
```

The script builds a deliberately simple generic-burden score from the nine structural features whose no-T1 association survived the census refresh:

`constrainedObjects`, `turnConstraintLoad`, `constrainedObjectDensity`, `requiredPathLength`, `portals`, `requiredPathCoverageRatio`, `mustTurn`, `surround`, `blocks`.

It averages within-population z-scores, divides the population into equal-count burden bands, and reruns the same frozen pairwise A-only/B-only analysis inside each band. This is **nuisance stratification**, not a calibrated difficulty model and not a production selector.

Outputs by default:

- `reports/stress/technique-niches/2026-09-03/difficulty-stratified-relative-advantage.json`
- `reports/stress/technique-niches/2026-09-03/difficulty-stratified-relative-advantage.md`

The useful question is: which structural separators recur in multiple bands with both sides adequately represented? Persistence weakens the explanation that the association is merely generic difficulty. It still does not establish causality.

## How to spend positive findings

### Stable plain-vs-mechanic-bucket effects

First query the existing variant-family dataset for parents where controlled portal/intersection/must-cross transformations flip plain-vs-bucket response. Use whole parents as independent units. Do not generate new variants unless the existing dataset lacks the required transformation.

If a family boundary survives, use source-stratified Corpus-2 solution profiles to test plausible mediators such as:

- portal-use/order diversity;
- must-cross order rigidity;
- objective-satisfaction depth;
- prefix/basin diversity;
- structural path-mode distinctiveness.

A positive mediator should nominate the smallest legal current-level/current-state descriptor or retention mechanism, not become a saved-solution routing feature.

### Width inversions with unstable structural explanation

Treat persistent outcome inversion + unstable coarse explanation as a mechanism-localization candidate, not a routing rule. Use matched burden/structure controls and bounded beam traces to ask where 2K and 5K retained frontiers first diverge in a load-bearing way. Width is already known not to be monotone; the unresolved question is which retention/churn geometry makes the smaller frontier occasionally superior.

### Orientation disagreements with weak static separation

Do not search harder for a global CW/CCW count-based selector. Use controlled symmetry/family cases and inverse-transform-aligned first-divergence traces to determine whether the disagreement is useful diversification, arbitrary representation bias, or a recurring harmful ordering/retention mechanism.

## Production-versus-isolated mismatch as a research axis

A further cheap extension is to treat the difference between expected isolated capability and actual production response as a residual, not merely two separate solved/unsolved labels. Useful cohorts include:

- structurally/census-expected easy but production-missed;
- structurally/census-expected hard but production-solved;
- high isolated support but production-missed;
- zero isolated support but production-solved.

Join these cohorts to lifecycle reach/work, provenance, solution profiles and traces only when they sharpen a current WS1/WS2 decision. This is a microscope for orchestration/search-policy failure versus missing repertoire capability, not a mandate for another classifier.

## CP-SAT/reference evidence extension

Do not reopen broad CP-SAT acquisition or static rescue prediction. Use retained exact/reference paths as **mechanism adjudicators** after a structural/technique contrast is nominated: did a policy/prune/merge discard a known-live state, or did it merely choose an unproductive search path? That is a higher-value use of the existing exact asset at the present frontier.

## Structure x technique-response evidence matrix

Future decision-bearing niche reports should record these columns, even if several are initially `unknown`:

| axis | question |
|---|---|
| outcome contrast | Which exact action/config A-vs-B disagreement is being explained? |
| generic difficulty control | Does the association survive comparable burden? |
| temporal stability | Does direction/explanation survive a solver/census refresh? |
| multiplicity/rarity | Is the claim concentrated on brittle singleton ownership or broad support? |
| family boundary | Does a controlled transformation flip response across independent parents? |
| solution-space mediator | Do source-controlled basin/path properties explain the structural association? |
| operational mechanism | Where do the searches first diverge in a load-bearing way? |
| production relevance | Does the mechanism affect current residual reach/work/capability? |
| legal intervention | Can the explanation become a generic level/state/search rule without historical lookup? |
| confirmation | Has it survived untouched parents/levels under a matched-work contract? |

This is a synthesis contract, not a requirement to fill every column before any small experiment. Stop escalating when a cheaper stage falsifies the premise.

## Execution handoff: work that still needs a full checkout

1. Run the new temporal-niche analyzer and commit its generated JSON/Markdown if outputs validate the expected eight-pair mapping.
2. Run the difficulty-stratified analyzer; inspect denominator adequacy before interpreting any recurring effect.
3. Rank only contrasts that are both temporally credible and difficulty-robust enough to deserve causal follow-up.
4. For the top one or two contrasts, query the existing family dataset branch (`claude/variant-levels-solver-insights-tpk4qg`) for controlled response flips. Do not generate variants first.
5. Generate/use Corpus-2 source-stratified solution profiles for those selected cohorts; control provenance source so discovery method does not masquerade as basin structure.
6. Use representative/all-known-basin extinction and bounded operational tracing only for distinctions still unexplained after family/profile evidence.
7. Translate any recurring mechanism into the smallest legal generic descriptor/intervention, then use independent parents/levels and matched `workSpent` before production promotion.

## Stop conditions

- If temporal direction does not survive, do not build a scheduler rule around the old niche explanation.
- If an effect disappears inside generic-burden strata, classify it as likely broad-difficulty confounding unless stronger causal evidence says otherwise.
- If existing family transformations do not reproduce the association, do not generate a large new family campaign merely to force it.
- If solution/profile and operational evidence do not reveal a compact recurring mechanism, leave the association descriptive.
- If the only useful predictor is historical level identity, family identity, saved solution or census winner, it is not a legal cold-solver intervention.
- Do not reopen richer generic topology, giant feature models or bulk variant generation absent materially new mechanism evidence.
