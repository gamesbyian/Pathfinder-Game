No later ordinary solver-dispatch run appears after `35391933756` in the workflow-dispatch history examined here; the later 2026-09-19 dispatches are CP-SAT/reference work, not ordinary solver failure-response producers.

## Why not backfill from native attempts?

The older targeted artifacts contain useful forensic stage/attempt telemetry, and they remain valid evidence for their original questions. But retroactively projecting those heterogeneous, selectively dispatched runs into a pseudo-current failure-response population would violate the integration plan's own rules:

- the populations were selected for other experiments, not WS2 prevalence;
- their commits/configurations/budgets differ;
- solved controls are not consistently present;
- they predate the compact publication/protocol-identity contract now intended to make longitudinal joins explicit.

They may nominate a specific question, as R00044 already did. They should not estimate current failure-phenotype prevalence.

## Consequence for Phase 3

Phase 3 Stage A is **tool-ready but data-blocked**.

The next maintained current-boundary run that naturally covers a useful residual/control population should emit the standard compact response automatically. Once such rows exist, `npm run research:query-failure-response -- --in=...` can perform the prespecified parent-level reconnaissance without another instrumentation project.

Do not launch a large run solely to populate a database. If WS2 requires a dedicated acquisition before another normal producer happens naturally, freeze a mechanically selected residual plus protocol-compatible solved-control population first and use the smallest maintained producer that already publishes compact failure response.

## What remains immediately useful

Existing pre-contract native attempts remain legitimate for narrow, explicitly selected mechanism microscopes and experiment design. They are not discarded. This audit only rejects treating them as a representative post-contract compact-response corpus.
