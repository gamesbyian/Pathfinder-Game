# Stress-corpus research-resource audit

> **Status:** concluded-positive with guardrail/tooling repairs implemented on `chatgpt/stress-corpus-resource-audit-2026-09-13`.
> **Scope:** published levels, stress Corpus 1, stress Corpus 2, and the in-envelope challenge corpus as research evidence infrastructure.
> **Decision:** keep corpus bytes/history intact; improve evidence ancestry visibility and invariant coverage rather than rewriting historical metadata.

## Bottom line

The current corpus files are structurally healthier than their surrounding tooling implied. A fresh census over all 2,162 rows found no missing persistent ids, no missing provenance/history, no cross-corpus id collisions, and no exact structural duplicates under structural fingerprint v2.

The main weakness is therefore not corrupted corpus data. It is **evidence-status opacity**: historical corpus headers, row-level provenance, current research role, generator ancestry, and independence assumptions are easy to conflate.

That matters because Corpus 2 is now heavily mined development/capability material even though its generation-time header truthfully records that the production solver had not yet been run when it was created. Corpus 1 also contains a mixed retained population: its top-level header says generator `1.0.0`, while row provenance shows 79 of 102 retained rows were generated by `1.1.0`; those 79 rows are not members of the older A-F `generationBatch` strata.

The audit therefore treats top-level corpus metadata as **generation-history metadata**, not as a timeless statement of current evidence status or a substitute for row-level ancestry.

## Empirical census

The one-shot census used the repository's canonical structural fingerprint payload and row provenance rather than names or positions.

| Corpus | Rows | Missing id | Missing provenance/history | Dominant retained ancestry |
|---|---:|---:|---:|---|
| published | 160 | 0 | 0 | mixed/backfilled historical authorship |
| stress Corpus 1 | 102 | 0 | 0 | 23 generator 1.0.0; 79 generator 1.1.0 |
| stress Corpus 2 | 1,700 | 0 | 0 | generator 1.1.0 / `random-uniform-v1` |
| envelope | 200 | 0 | 0 | generator 1.1.0 / `in-envelope-v1` |

Across all 2,162 rows:

- global persistent-id collision groups: **0**;
- exact structural-fingerprint duplicate groups: **0**;
- cross-corpus exact structural duplicate groups: **0**;
- within-corpus exact structural duplicate groups: **0**.

This is good evidence against literal duplicate contamination. It is **not** evidence that rows are independent draws. Generator ancestry, shared batches, family-like construction effects, symmetry/near-equivalence, and repeated research selection can still couple observations.

## Findings

### 1. Current evidence role and generation-time metadata were too easy to confuse

Corpus 2's file header says the production solver had not yet been run against it. That statement describes the corpus at creation time and should remain preserved as history. It is no longer a correct description of the corpus's current research role.

The fix is not to rewrite the file header. `corpus-query` now reports generation metadata separately from row-level evidence ancestry, and row descriptors expose provenance origin, methods/actions, generator versions, corpus names, history-event count, and generation batch.

### 2. Corpus 1 is a mixed retained population

The top-level Corpus 1 header reports generator version 1.0.0. Row provenance shows 23 retained 1.0.0 rows and 79 retained 1.1.0 rows. The 23 older rows carry A-F batch identity; the 79 newer rows do not.

Any analysis that treats Corpus 1's header generator version or A-F batches as properties of all 102 rows is therefore wrong. Use row provenance/generation-batch fields when stratifying.

### 3. Envelope was first-class evidence but second-class in invariants

The current research authorities and query aliases treat envelope as a first-class challenge corpus, but both `check:level-provenance` and `check:corpus-level-formatting` covered only published/C1/C2.

The fresh census found no current envelope corruption, so this was latent guardrail debt rather than an observed data defect. The branch extends both invariants to envelope.

### 4. The cheap query surface hid the ancestry needed for safe stratification

`corpus-query` already supported mechanics, routing regime, tags, objective ranges, and deterministic sampling, but discarded `level.provenance`. That made the scientifically important distinction between generator strata or provenance histories harder to see than geometry/mechanics.

The branch adds row-level evidence ancestry to descriptors and summary output plus filters for:

- `--origin=`
- `--method=`
- `--action=`
- `--generator-version=`
- `--corpus-name=`
- `--batch=`

This makes independence-aware cohort construction possible without ad hoc JSON parsing.

### 5. Exact deduplication is healthy, but dependence remains broader than identity

Structural fingerprint v2 found no exact duplicate puzzle structures among the four corpora. That closes one straightforward contamination hypothesis.

Do not promote that result into a claim that all rows are independent. The next rung, if a decision needs it, is purpose-specific dependence analysis: common generator/seed strata, symmetry-equivalent or near-equivalent structures, repeated selection/mining history, and any generator-specific clustering relevant to the tested mechanism.

A global all-pairs similarity project is not justified merely because it can be done. Use it when a research conclusion actually depends on an independence assumption that exact identity and ancestry stratification cannot answer.

## Durable changes from this audit

1. `corpus-query` separates generation metadata from row-level evidence ancestry and exposes ancestry filters/summaries.
2. `corpus-query` tests now cover provenance filtering and metadata separation.
3. `check:level-provenance` covers envelope, so ids/provenance are globally checked across all four first-class corpora.
4. `check:corpus-level-formatting` covers envelope as well.
5. `scripts/stress/corpus-evidence-audit.mjs` is retained as a read-only census tool for future corpus-health checks.

No corpus data file is rewritten by this audit.

## Research-use rules going forward

Treat corpus headers as historical generation metadata. Treat row provenance as the authority for row ancestry. Treat current research role as a separate, evolving property owned by the research authorities/asset registry.

When reporting solve rates or treatment effects, state the population at the row level when mixed ancestry matters. Do not describe Corpus 1 as uniformly generator 1.0.0 or uniformly A-F. Do not describe Corpus 2's old generation-time virginity as current holdout status.

Do not count rows as statistically independent merely because ids and structural fingerprints differ. Preserve generator/batch/family context whenever it could create a shared unit.

## What this audit did not establish

- It did not measure symmetry-equivalent or approximate structural duplication.
- It did not reconstruct every historical run that has mined each row.
- It did not prove that Corpus 2 remains representative of an untouched distribution; current authority already says otherwise.
- It did not redefine production promotion gates or corpus roles.
- It did not justify per-level runtime routing from corpus ancestry.

Those remain separate questions and should be pursued only when they bear on an actual solve-rate decision.
