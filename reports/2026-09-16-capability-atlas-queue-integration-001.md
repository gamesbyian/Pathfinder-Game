# Capability-atlas queue integration 001

> **Status:** concluded-positive
> **Last evidence:** 2026-09-17 — reasoning-capability atlas, stop-condition reconciliation, archaeology register, current WS2 queue, and pending separator census PR #1827.
> **Decision:** promote multiple bounded premise-acquisition questions into the live solver queue in parallel, while keeping heavyweight solver architectures gated behind positive premise evidence.
> **Remaining gate:** execute the newly prepared lane-specific falsifiers; no production treatment is earned merely by this integration.

## Goal

Convert the capability-atlas investigations into more open, testable solve-acquisition premises without recreating the earlier failure mode where every speculative architecture became implementation debt.

The queue should maximize useful premise throughput, not maximize the number of named ideas.

## Main queue-shape change

The previous queue was mostly serial: separator census -> fresh exact siblings -> topology -> smaller reconciliations -> architecture nursery.

That structure unnecessarily blocked several cheap questions that can be answered from retained evidence or existing exact-labelled states. The live queue is now organized as bounded **parallel premise-acquisition lanes**.

Heavy treatments remain serial behind a positive lane result.

## Newly active / reopened lanes

### Solve-local typed knowledge reuse

Reopened from the August learned-connectivity evidence, but **not** as the rejected cross-level reason checker.

Key evidence:

- reached-set shape sharing: 83.1%;
- literal exact-state sharing: 52.6%;
- cross-level-spanning shape records: only 8.8%.

The old experiment correctly rejected a fixed cross-level checker. The later level-blindness correction makes within-invocation board-specific derivation/reuse a different legitimate premise.

First gate: retained-evidence rediscovery + cheap sound-key economics. No blackboard until one typed fact family pays.

### Per-instance relational feasibility

Promoted because several old lines closed a descriptor or implementation form rather than the semantic question.

Initial subquestions:

1. future-intersection commitment realizability;
2. constrained-event feasibility through a current-input event/region/interface;
3. actual residual-interface commutativity.

Historical H1 vocabulary, blueprint implementations, detour gadgets, and the dirty-revert arbitrary-target primitive are constraints/lineage, not clean semantic closure.

### Dependency-defined causal revision

Promoted as distinct from broad positional/prefix repair.

Question: can exact-labelled failures be explained by a compact set of coupled earlier commitments, materially smaller than rollback/path difference, such that one targeted revision can preserve unrelated useful structure?

First gate is observer-only. No LNS/backjump operator until the causal interface is demonstrated.

### Fresh exact siblings / DEAD cores

Remains central and now acts as a shared evidence asset for several separately prespecified microscopes rather than one isolated experiment.

### Separator/interface composition

Pending PR #1827 reports 121/390 Class-5 levels with balanced narrow width<=4 static/mechanic-aware interfaces. The next useful question, if that result lands, is **contract-state size**, not another separator prevalence census.

### Complete-path LNS falsifier

Moved from deferred future work into the live independent-architecture nursery because its first test is cheap and does not require implementation: determine whether relaxed whole-path candidates are actually locally repairable toward accepted solutions.

## Still bounded/supporting

- Class-3 exact-action dose: reopen only if retained exact-action participation/work is cheap to recover.
- Card-E quotient: one interpretable parent-held-out hypothesis-discovery pass only.
- topology microscope: join to separator/fresh-sibling/relational evidence where possible rather than create a parallel feature hunt.

## Deliberately not reopened now

### Forced-chain / macro traversal

The premise may matter for work/speed, but current solve-acquisition priority asks where new solves come from. Without evidence that chain compression unlocks capability rather than merely reduces work, this stays deferred to profiling/speed work.

### Generic transposition / full MITM

Existing sound-identity evidence is too negative. A new compact interface/equivalence from the active lanes could reopen a materially changed form later.

### General blackboard / proof store

A generic framework is not a premise test. One concrete typed fact family must first demonstrate rediscovery, safe reuse, and economics.

### Production exact solver

The live question is bounded exact *knowledge* for one earned query, not appending a second global solver.

## Operational ordering

Single-agent preferred order:

1. reconcile separator PR #1827 result if/when merged;
2. harvest fresh exact siblings;
3. run per-instance relational feasibility on existing/fresh exact states;
4. run retained-evidence solve-local rediscovery;
5. run dependency-defined revision observer;
6. complete bounded Class-3/Card-E reconciliations;
7. run complete-path LNS cheapest falsifier.

With parallel agents/resources, the first gates for solve-local rediscovery, relational feasibility, causal revision, Class-3/Card-E reconciliation, and LNS may proceed concurrently because they do not mutate production policy and mostly consume retained/offline evidence.

## Promotion rule

Every active premise follows:

`semantic gap -> historical stop-condition reconciliation -> cheapest falsifier -> one smallest consumer/prototype -> matched-work economics -> broader architecture only if earned`

This is the core protection against both failure modes the repo has experienced:

- starving new capability because an old narrow null was over-generalized;
- building large solver machinery before the premise itself was demonstrated.
