## Exact implementation seam and accounting

`evaluatePrunedMove` in `modules/solver/hard-prune-pipeline.ts` calls `isConnected(next,state,level,prep)` only when the caller requests scheduled connectivity and `PRUNE_CONNECTIVITY` remains enabled. All earlier hard-prune checks can reject before this call, so **identical parent paths do not establish the same charged child connectivity calls**. The shared `PrepLevel` already persists across attempts of a single `solveLevel`; a per-solve memo can potentially share across scorer profiles without crossing level boundaries.

`isConnected` charges `CONNECTIVITY_WORK_UNITS=12` before its flood and first checks the atomic strict work cap, then uses mutable flood scratch, pending MP/MC masks, remaining intersection budget, flipper masks, cell visit and consumed-axis arrays, goal reachability and remaining counted path length. It evaluates connectivity policy switches including `PRUNE_MC_RESERVED_WALL`, `PRUNE_CONNECTIVITY_AXIS_EXHAUSTED` and `PRUNE_CONNECTIVITY_VOLUME_PORTAL`; it also has research-only certificate and rejection observers. A memo that omits *any* relevant dependency, conflates distinct revisions or returns a truth value without producing needed observer/flood side effects could silently change behavior. The returned Boolean alone is **not sufficient** when BC1's immediately following shadow reads `_reached` flood scratch through `connectivityResearchSnapshot(...,reachedIsFresh=true)`.

The existing `connectivityRejectionObserver` sees only negative results. Existing `beamResearchObserver.includeParentExpansionWork` records work **after expansion** and cannot separate `applyMove` units from the 12-unit flood operations, nor distinguish changes in scheduled timing. Accordingly the measured 48,066 units cannot currently be called 48,066 units of savable connectivity work. Dividing by twelve would only yield an impossible-to-justify upper envelope of at most 4,005 floods, not an empirical hit rate.

## Minimal observer design, before any cached read

1. Add a research-only optional `observeConnectivityCall` hook at the actual scheduled `isConnected` entry/return seam, counting calls by real attempt ordinal/scorer and exact work charge. Instrument both Boolean outcomes, including early rejections, with the same decision and charged work as the uninstrumented control. Allow no recursion, mutation of the flood, scoring or extra meter writes. Do not attach this hook to unrelated unscheduled false-goal connectivity.
2. For an *experimentally exact* identity, use the full literal path **plus** full normalized level identity, call position, state-dependent connectivity inputs (visited cells, per-cell edge-axis use, pending objective masks, required/intersection status, flipper state, any portal state relevant to flood), and the effective connectivity flags. Start conservatively with a serialized complete state/config fingerprint and compare all primitives on hash collisions; shrink only after independent property evidence proves omitted fields irrelevant. Include `runConnectivity` scheduling provenance and never mix scorer-specific child scores with this independent predicate.
3. Count a later cross-scorer hit only if the first same-key recorded result was produced by an **earlier** real attempt ordinal, the target call would have executed, and both results agree. If full scratch observation is required by a downstream consumer (including BC1), classify the call separately as *Boolean reusable but flood not safely elidable*. Track these cases rather than hand-waving them away.
4. Record `calls / unique keys / cross-profile later hits / 12×later-hit upper-bound charge / result disagreement / memory key bytes / attempted lookups` **by independent source parent**, alongside full exact OFF/ON solver attempt/status/work/nodes/solution parity. Cap retained state records and explicitly mark censored sessions invalid for prevalence or economics. Require a measurable amount of *real* duplicate scheduled connectivity calls before constructing a consumer.
5. Only after the observer qualifies should a separate default-OFF read-only versus memo treatment measure actual search-time cost, flood scratch dependencies, exact canonical budget differences and solve-set impact under identical 250k **total** budgets on new source-independent parents. Cached calls must still adhere to the work-accounting contract; a treatment that reduces canonical charge without charging lookup may change stage allocation and must be assessed as such, not compared using raw wall time alone.

## Fail-closed conditions

- Same literal path but different semantic state/config: distinct keys or abort, never accept a hash-only equivalence.
- Earlier-fact producer has not completed or is from an equal/later ordinal: not a reuse opportunity.
- First call was not scheduled, or caller was already hard-pruned: not a hit.
- Positive result but downstream implementation needs the flood's `_reached` scratch: Boolean cache may not bypass the fill.
- Observer uses enough memory that it crowds out the near-typical intended environment: close or impose a smaller independent stratum, rather than claiming victory from an unbounded map.
- No material charged repeated connectivity among the two source-positive parents: stop this immediate consumer form. Consider other scorer-independent per-parent computations, not full-node scoring reuse or blind pruning.

**Priority:** This is currently the best characterized potential reuse lane after PG-L 006, but it is still an interface contract. Do not mistake documentation for the required new experiment or new cold solve.
