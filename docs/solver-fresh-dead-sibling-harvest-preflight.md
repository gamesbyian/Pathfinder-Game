# Fresh exact LIVE/DEAD sibling harvest preflight

> **Status:** DESIGNED / NOT YET EXECUTED.
> **Question:** can the current residual supply a fresh, independently selected exact-labelled sibling population large enough to resolve the population-limited DEAD-core result and support the next topology / exact-reasoning microscopes?
> **Queue position:** WS2 premise acquisition, immediately after or in parallel with the separator/decomposition census.
> **Evidence role:** reusable research asset acquisition. This is not a solver treatment.

## Why this asset is earned

The minimal DEAD-core pilot was informative but exhausted: 3/4 exact-DEAD B2 states became feasible after relaxing exactly one pending commitment, while the fourth required a larger or different core. That result earned a fresh population; it did not earn runtime nogoods.

The same missing asset now blocks several related questions. A fresh sibling set can support:

- DEAD-core size / recurrence and the required “rejects DEAD while sparing LIVE” test;
- per-instance topology microscopes on independent rows;
- bounded exact-query economics;
- richer behavioral-state / hypothesis-discovery work;
- future backward/interface feasibility tests.

Create one well-provenanced population instead of repeatedly mining tiny bespoke sets.

## Selection contract

Freeze candidate parents from the **current production residual before exact labelling**. Prefer current Class 5, with Class 4 permitted only as a separately reported secondary stratum when it provides a necessary mechanism contrast.

Selection must use runtime-legal or neutral structural criteria only. It must not use:

- exact LIVE/DEAD labels;
- known accepted-solution geometry;
- historical winner identity;
- capability-memory membership;
- prior DEAD-core outcome;
- whether the candidate appears likely to produce a small core.

Keep the parent level as the independent unit. Multiple sibling prefixes from one parent increase within-parent resolution, not sample size.

## Sibling construction

Use an existing audited prefix/frontier harvesting path where possible. The goal is to obtain same-board sibling states that differ in a bounded, recorded set of commitments while remaining realistic products of legal current search.

For every frozen state record at minimum:

- parent level and source commit;
- full current prefix/state identity needed for replay;
- endpoint, prefix length and remaining length;
- current intersection count and remaining intersection obligation;
- pending must-pass / must-cross obligations;
- portal/filter/flipper state and relevant path-history state;
- production score/rank only as descriptive metadata, never as a label surrogate;
- exact selection reason and stratum.

Avoid selecting only top-rank failures. Include enough within-parent sibling diversity to permit both LIVE and DEAD outcomes without conditioning on those outcomes.

## Exact labelling

Run the existing CP-SAT/reference prefix pipeline after the frozen population is committed.

Each state is one of:

- `LIVE`;
- `DEAD`;
- indeterminate/timeout/error.

Timeout/error is never DEAD. Record exact-tool identity/config, source commit, state fingerprint and any witness/referee validation.

## Sizing rule

Do not size the campaign from the observed 3/4 small-core rate in the exhausted B2 set.

Use a two-stage harvest:

1. a bounded pilot large enough to estimate the **exact-DEAD opportunity rate** under the new selection contract;
2. only if needed, extend using that observed opportunity rate to obtain a decision-bearing DEAD sample across independent parents.

The target is not a magic raw-state count. The decision-bearing requirement is enough exact-DEAD states across independent parents to test whether small cores remain common and enough matched LIVE siblings to test collateral/specificity.

## First consumer: DEAD-core confirmation

For every exact-DEAD state, apply the existing single-commitment relaxation hook first. Do not jump directly to combinatorial core search.

Report:

- whether a size-1 core exists;
- commitment type and identity;
- number of candidate commitments tested;
- exact-query cost;
- for unresolved states, whether a bounded size-2 pass is justified by the observed candidate count.

Then test the moonshot’s missing half: whether the derived conflict/core rejects other DEAD siblings while sparing LIVE siblings from the same parent and, separately, from other parents when the core can be normalized generically.

Advance toward runtime conflict learning only if cores remain small at useful prevalence **and** their runtime-derivable form has useful specificity without unacceptable LIVE collateral.

## Secondary consumers

After the DEAD-core analysis is frozen, the same exact-labelled population may support topology or behavioral analyses provided those questions are separately prespecified before inspecting their target features against labels.

Do not repeatedly tune descriptors on this set and then call later analyses confirmation. Once used for feature discovery, it becomes development evidence for that question.

## Stop conditions

- **Exact-label starved:** too many timeout/error states to support the intended comparison.
- **DEAD-starved:** the frozen selection produces too few exact-DEAD states; revise selection using neutral opportunity information, not inspected causes.
- **Sibling-starved:** parents rarely provide useful within-board state variation; do not inflate evidence with many nearly identical descendants.
- **Core-negative:** size-1 and bounded size-2 cores are mostly absent or effectively board-unique with no useful rejection power. Close the runtime nogood line in that tested form.

## Guardrails

- This asset exists to open premise gates, not to become a hidden runtime lookup table.
- Exact labels and derived cores are offline truth only until a generic current-input derivation procedure earns production use.
- Preserve parent-level independence and complete selection history.
- Do not use known witnesses to label an alternate prefix LIVE unless the exact/replay contract genuinely proves that prefix.
- Reuse this asset across questions only with explicit evidence-role accounting so one labelled population is not mistaken for independent confirmation.
