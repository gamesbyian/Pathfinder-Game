## Queue-wide rules

Every active item follows **premise → smallest value-of-information pilot → explicit success/stop gate → bounded implementation → confirmation → broader integration**.

- Use `workSpent` for cross-technique allocation; raw nodes are within-technique diagnostics. `baseWorkBudget` is the preferred name for deterministic base allocation; `strictTotalWorkBudget` is the current true whole-solve work envelope.
- New actions/configs expand the menu, not the default total budget.
- Selected/tuned treatments need independent confirmation proportional to selection pressure; cross-generator transfer is reserved for broad/high-selection-risk claims. See [`solver-evaluation-evidence.md`](solver-evaluation-evidence.md).
- Level-blindness is not generalization.
- A clear negative closes the tested form unless materially new evidence changes its premise.
- Prefer locked confirmation pools partitioned into one-use blocks when repeated selected candidates are expected. Spend the block whose outcomes influence design; untouched sibling blocks remain available. A fresh one-off cohort is still fine when cheaper.
- Major capability refreshes should emit an output-only delta digest: gain/loss IDs, winner stage/action, per-level work/attempt deltas, and aggregate work split across prior solves/new solves/still-unsolved.

### Immediate execution priority

After #0's already-prespecified production-equivalent restart pilot, **#2 is the next implementation priority and the default place to spend solver-infrastructure effort**. Its behavior-preserving substrate work may proceed in parallel with #0 when it does not change the search treatment being measured.

Do not skip from #0/#2 to lower-ranked speculative solver work merely because the budget migration is less glamorous. The remaining budget debt can invalidate or muddy later scheduler comparisons by letting a nominal wall deadline resize search. Clearing it is research-enabling work, not cosmetic architecture.

Within #2, use this order unless fresh evidence changes it:

1. **Ownership/parity first:** finish explicit work ownership (`BudgetEnvelope` projection, attempt/stage budget context, session-isolated multi-solve work accounting) with no intended solve-policy change.
2. **Equal-work evidence substrate:** extend isolated/census tooling where scheduler pricing still relies on node-depth-only evidence.
3. **One additive tier at a time:** replace ms-derived dose with an explicitly equivalent work dose, prove parity under the current policy, then remove that site from the CI allowlist.
4. **Whole-solve invariant:** when the legacy inventory is gone, widen deadline-independence tests from the main ladder to the full production solve.
5. **Then reprice:** only then treat work quanta/tranches as scheduler policy variables under a fixed total-work envelope.

If an ostensibly structural conversion changes solved sets, attempt order, seeds, or material `workSpent`, stop classifying it as migration and route it through the scheduler experiment/confirmation pipeline.
