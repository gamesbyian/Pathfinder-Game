## Object structure

The canonical proposition inventory is split across:

- `docs/solver-premise-space-register.csv` — 92 rows;
- `docs/solver-premise-space-extension-2026-09-17.csv` — 26 rows;
- `docs/solver-premise-space-extension-2026-09-17b.csv` — 20 rows;
- `docs/solver-premise-space-extension-2026-09-17c.csv` — 4 rows.

The baseline register and extensions do not have identical schemas. Common fields include proposition identity, kind, stratum, domain, stage, proposition text, status, population, weight, evidence summary, solve-count link, gap type, and source paths. The baseline additionally has explicit `dependencies`, `interactions`, `adjacent_unasked`, and `architecture_epoch`; the extensions instead add `claim_type`, `scope`, `system_locus`, and `mechanic_resources`.

The relation substrate is also layered:

- `solver-premise-space-graph.json` contains untyped pair edges rooted in the baseline register;
- `solver-premise-space-relations-v2.json` adds typed semantic edges and a declared source→target direction;
- `solver-premise-space-relations-v3.json` is a delta relation file for later proposition IDs and includes both proposition-ID endpoints and prose/concept endpoints.

The frozen hardening overlay adds cross-cutting structures: authority classes, maturity stages, temporal-conditioning dimensions, contradiction candidates, semantic-sibling families, implicit defaults, asymmetry families, and ontology-stress-test objects. These are part of the fixed object and must not be mistaken for conclusions generated by this investigation.

## Interpretation cautions

1. Absence of a relation is explicitly not evidence of independence.
2. Relation vocabularies differ between v2 and v3, so mechanically combining them requires normalization or preservation of vocabulary provenance.
3. Some relation endpoints in v3 are concepts expressed as prose rather than canonical proposition IDs.
4. CSV generations have schema drift. Cross-generation analyses must distinguish a genuinely missing value from a field that did not exist in that generation.
5. The map mixes proposition content with research-state metadata, evidence summaries, scope language, and source provenance. A pattern in metadata may therefore reflect curation practice rather than solver reality.
6. The hardening overlay is itself a curated interpretive layer over the proposition inventory. Analyses using it must identify when an observation depends on that representation.
7. The purpose of this phase is only to understand the object. No higher-order mining findings are recorded here.

## Frozen object capabilities

The object can directly support analyses of proposition text, categorical metadata, evidence summaries, declared scopes, source paths, explicit relation structure, and hardening annotations. It can support only cautious inference about missing relationships or absent concepts because incompleteness of encoding is not equivalent to conceptual independence or nonexistence.

The independent interrogation method will be frozen separately before substantive mining begins.
