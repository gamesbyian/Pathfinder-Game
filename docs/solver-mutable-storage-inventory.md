# Solver mutable-storage inventory

This inventory covers solver storage whose physical lifetime can outlive one helper call: module scratch, per-solve pools and memo tables, and work counters. “Owner” means the code allowed to write the storage. JavaScript module instances are worker-local, while `PrepLevel` is created fresh per `solveLevel()` call; the rows below distinguish those scopes explicitly.

| Module / storage | Owner and maximum capacity | Reset / overwrite contract | Nesting and lifetime boundary |
|---|---|---|---|
| `topology.ts`: `_reachQ`, `_reachGenBuf`, `_reachGen` | The plain connectivity flood fill. Queue: 512 packed cells (the supported grid is at most 225); tags: `KEY_SPACE` packed keys; generation: uint32-compatible. | A call starts a new generation. Tags are logically cleared by changing generation; at `0xffffffff`, the whole tag buffer is cleared and generation restarts at 1. Queue entries through the current tail are overwritten. | Connectivity calls are synchronous and cannot nest through current call paths. Physical tags can cross levels, gates, attempts, and sequential jobs in one worker, but old generations are logically invisible; rollover removes even that. Oversized bit-row grids use this BFS fallback. |
| `topology.ts`: `_rowReached`, `_rowPassable`, `_rowVisAny`, `_reachMode` | The bit-parallel connectivity fill, one word per row, capacity `MAX_BITROW_DIM` (30 rows and columns). | Every row in the active band is rebuilt; reached rows are cleared before growth. `_reachMode` selects only the representation written by the latest call. | Synchronous/non-nested. Words can physically survive calls and levels, but rows outside the current band are never observed and active rows are overwritten. Dimensions above the declared maximum fall back to BFS. No cross-worker state. |
| `lower-bounds.ts`: `_mpRemainScratch`, `_mcRemainScratch` | `mustPassLowerBound` and `mustCrossLowerBound`, respectively; each holds `MAX_MST_K` (16) objective indices. | Each owner writes indices `0..remainLen-1`; consumers use the explicit length, never stale tail slots. Separate arrays prevent must-pass/must-cross contamination. | Current calls are synchronous and neither nests the other. Values may remain across levels/gates/attempts/jobs in one worker but are outside the next call's explicit length. More than 16 objectives skips MST tightening and retains the allocation-free individual lower bound. |
| `lower-bounds.ts`: `_mstEdges`, `_ufPar` | Shared Kruskal implementation used after either remaining-index scratch is complete. Edge capacity is `MAX_MST_K + C(MAX_MST_K,2)` triples; union-find capacity is `MAX_MST_K + 1` nodes (objectives plus current position). | All `eCount` edge triples are written before sorting; union-find entries `0..nodeCount-1` are initialized before Kruskal. | Not reentrant, but current lower-bound calls never nest. Physical values cross calls and logical ownership categories, while explicit counts prevent observation. The callers enforce the 16-objective fallback before entering MST code. Worker-local. |
| `PrepLevel._mpLowerBoundCache` | `mustPassLowerBound`; lazily memoizes exact lower-bound values by `(pos, mpVisitedMask)`. Schema-valid normalized must-pass/must-turn union is at most 30 bits. | Cache entries are never cleared during one solve. The key reserves the full 30-bit visited-mask space, so distinct schema-valid states cannot alias by packing. A hit must return exactly the value a fresh computation would return. | **Per `solveLevel()`, but intentionally cross-attempt and cross-gate.** This is mutable stage history even though it cannot cross separate solves. Warming may reduce CPU cost only; it must not alter bounds, ordering, pruning, or capability. Include cache-empty vs cache-warm controls in fresh-vs-preceded P0 diagnosis. **2026-09-03: run for real** via the existing `STRATEGY_LOWER_BOUND_MEMO` ablation bypass — 50/50 sampled solves matched exactly with the cache fully disabled; see [`../reports/2026-09-03-lower-bound-memo-cache-empty-warm-control.md`](../reports/2026-09-03-lower-bound-memo-cache-empty-warm-control.md). |
| `PrepLevel._mcLowerBoundCache` | `mustCrossLowerBound`; lazily memoizes exact lower-bound values by position, pending mask, crossing count, and first-cross axis state for supported cache cardinalities. | Never cleared during one solve. Levels above the cache's explicit cardinality limit bypass memoization and compute fresh. A hit must equal the uncached computation exactly. | **Per `solveLevel()`, intentionally cross-attempt and cross-gate.** Same semantic-inertness requirement as the must-pass memo: history may affect cost, never result. Include it in stage-history state snapshots/clearing controls. **2026-09-03:** same result as the must-pass memo's control — see the report linked above (both caches share one check, `STRATEGY_LOWER_BOUND_MEMO` bypasses both). |
| `scoring.ts`: `_pooledMpCur`, `_pooledMcCur`, `_pooledMcIsApproach`, `_pooledMcTargetArr`, `_pooledWeights`, `_pooledCtx` | `buildCurUrgencyContext`; 32 must-pass and 32 must-cross slots plus one context/weights record. | Every slot below the current level's objective counts and every enabled context field is overwritten. Readers are count-bounded. Disabled must-cross fields are explicitly nulled. Calls over either capacity allocate a fresh context and arrays. | The returned pooled context is borrowed until the current sibling-scoring loop ends. Audited call paths do not recursively build another context while borrowed. It can be overwritten across levels/gates/attempts, intentionally, but not shared across workers. Callers must not retain it. |
| `scoring.ts`: `_sas` | `scoreAndSort`; four scores, matching the maximum four grid neighbors. | Slots `0..neighbors.length-1` are overwritten and only those slots are sorted/read. | Synchronous/non-nested in current call paths. Stale values can cross any same-worker boundary but are unobservable. Portal forcing does not increase the four-neighbor input contract. |
| `PrepLevel._stateBufs[STATE_BUF_DFS/BEAM/REPAIR]` via `search-state.ts` | One `visited[KEY_SPACE]` and `edgeUsage[KEY_SPACE]` pair per opted-in search call-site slot, lazily allocated on the current prepared level. DFS, beam, and repair own separate slots. | `createState` clears every in-grid cell in both arrays, then applies start-cell state. All other semantic fields (`path`, masks, counts, flags, surround state) are newly allocated or initialized on every call. Out-of-grid cells are unreachable by normalized moves and deliberately not cleared. | A slot's owner must not nest itself. The buffers may be reused across gates/attempts **within one `solveLevel()`**, because those share one `PrepLevel`; they cannot cross levels, separate solves, or worker jobs because each solve creates a fresh prep. This per-prep scope replaced the former module-global pool in `ff3ac0f` to make concurrent same-realm solves safe. Calls without a slot allocate fresh arrays. |
| `work-meter.ts`: module-global `workMeter.units`; `PrepLevel._workMeter.units` | Both count the same canonical work unit. The prep-local counter is the internal budget/accounting authority for one solve; the module-global counter is legacy cumulative realm/process telemetry for sequential discovery tooling. | `prepLevel()` initializes its counter to 0. The global counter is monotonic. `applyMove()` and `isConnected()` increment both. | Concurrent solves have independent prep-local counters and therefore cannot consume each other's budgets. The global counter may span levels/jobs and must not be used as a per-solve authority. See [`solver-budget-determinism.md`](solver-budget-determinism.md). |

The immutable debug flags, LDS constants, and `EMPTY_KEYS` are excluded because their bindings and contents are not mutated. Per-solve memo caches are **not** excluded merely because they are scoped to `PrepLevel`: cross-attempt lifetime is exactly the boundary relevant to stage-history correctness.

## Stage-history invariant

For every mutable object above, distinguish **physical persistence** from **semantic persistence**. Reuse that exists only to save allocation or recomputation may change wall time, allocation pressure, or cache-hit counts; given the same explicit level/action/config/seed/work, it must not change legality, bound values, candidate ordering, randomness, work accounting, or solve capability.

When a fresh-vs-preceded result differs, snapshot or selectively clear each cross-attempt store that the receiving action can observe. A store is cleared as a suspect only when the difference survives that control or when its warm and fresh return values have been directly shown identical. Do not infer semantic innocence from ownership scope alone.
