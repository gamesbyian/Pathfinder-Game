# Class-5 controlled topology acquisition preflight

> **Status:** DESIGNED / NOT YET EXECUTED.
> **Question:** can a runtime-legal open-path topological coordinate distinguish exact completion feasibility between otherwise matched path states?
> **Queue position:** WS2 Class 5, after the live Class-4 and Class-2 gates.
> **Observer:** `modules/solver/open-path-topology-observer.ts`.
> **Construction contract:** [`human-parent-contrast-research.md`](human-parent-contrast-research.md).
> **Natural-evidence boundary:** the 2026-09-15 offline join found 28 exact-labelled rows in 26 controlled strata and zero natural LIVE/DEAD contrasts.

## Why construct evidence

The current observer has passed representation-level fixtures, but existing exact-labelled prefixes cannot test whether its lifted phase coordinates carry completion-feasibility information: there are no LIVE/DEAD pairs inside the same endpoint/geometry/reference-controlled stratum.

The next experiment therefore manufactures the missing **comparison**, not a desired outcome. Generation must be blind to exact labels and production-solver results. Exact labels are joined only after the candidate population is frozen.

The clean causal unit is a **same-board, same-endpoint, same-work-state path-prefix pair** whose two routes pass on different sides of one board-derived puncture. For fixed endpoints, the difference between their lifted phases corresponds to the winding of the closed loop obtained by following one route and reversing the other. This gives a deliberately strong topological contrast without endpoint closure inside the runtime observer.

## Primary question

Among prefixes that are matched on all non-history state needed for completion and differ materially in open-path phase around at least one deterministic board puncture, do exact completion labels ever split LIVE versus DEAD?

A positive result is evidence that path-history topology contains capability-relevant information omitted by the matched control state. It is **not** permission to route the production solver using the current observer.

## Pilot population

Use **three published human/editor-authored parents** as development parents. Parents may be previously inspected because this is premise discovery, not confirmation. Keep parent families as the independent units.

Target at most:

- 3 parents;
- 0-2 descendants per parent;
- 1-2 frozen prefix pairs per board;
- 12 prefix pairs total / 24 exact-label requests maximum.

Do not bulk-generate a Class-5 corpus.

Prefer published parents directly. Only create a descendant when the parent lacks a usable topological fork. If a descendant is required, use the smallest witness-preserving intervention available, normally `local-mutant` or one-object/block relocation through the existing human-parent/family generator. Never accept or reject descendants based on solver outcome or exact label.

Exclude portal-jump prefixes because the current observer intentionally abstains on them.

## Candidate construction: a topological fork

Start from a referee-valid stored/inherited witness path. Search for two witness anchors `A` and `B` and construct an alternative orthogonal `A -> B` segment such that replacing the witness segment creates a second legal prefix.

A candidate pair is admissible only when all of the following are established **before exact labelling**:

1. Both prefixes belong to the same board and end at exactly `B`.
2. The replaced segments have equal path length, so total prefix length and remaining length budget match.
3. Both prefixes are legal under path rules and have the same current self-intersection count.
4. Required-object progress and all other non-history mechanic state relevant at `B` match. This includes must-pass/must-cross progress and any filter/flipper/portal state that can affect future legality. If a complete control fingerprint cannot be derived reliably, stop and add the smallest explicit checker before acquiring labels.
5. The deterministic topology reference set is identical by construction because the board is identical.
6. Neither prefix contains a portal jump.
7. `endpointGeometryKey` is identical.
8. At least one `phaseTurns` coordinate differs by more than numerical tolerance (`1e-12`). Prefer forks where the two segments pass on opposite sides of a single puncture and the pairwise phase difference is approximately one full turn in the closed-loop comparison.
9. The candidate identity, parent/descendant identity, two prefix paths, control fingerprint, observer outputs and generation provenance are frozen before any exact outcome is inspected.

The known witness does not count as the LIVE adjudication for this experiment. Exact-label **both** members of every frozen pair.

## Exact-label stage

Use the existing exact/reference prefix pipeline. Each frozen prefix receives one of:

- `LIVE`;
- `DEAD`;
- indeterminate/timeout/error.

Timeout/error is not DEAD. Do not replace unresolved labels with witness logic or production-solver outcomes.

The exact-label run must record source commit, exact-tool identity/config, prefix identity, board fingerprint and pair identity. Keep siblings from one human parent in the same analysis partition.

## Primary analysis

For every exact-resolved pair report:

- parent and descendant identity;
- matched-control fingerprint;
- puncture/reference identity;
- both exact labels;
- per-puncture phase coordinates and pairwise deltas;
- whether the pair is label-concordant (`LIVE/LIVE` or `DEAD/DEAD`) or label-discordant (`LIVE/DEAD`).

Aggregate by **parent family**, not raw descendant count.

The first scientific target is simply whether clean phase-distinct, control-matched LIVE/DEAD pairs exist. Do not optimize a classifier, threshold or routing rule in this pilot.

## Frozen interpretation rules

### Premise earned

The open-path-topology premise advances when there are at least **3 exact-resolved LIVE/DEAD pairs across at least 2 independent human/editor parents**, with all control checks valid and the members materially phase-distinct.

This earns a microscope step: inspect the first-loss/completion boundary and derive the smallest generic runtime-safe capability or descriptor. It does **not** earn production routing of raw phase coordinates.

### Discovery only

One or two valid LIVE/DEAD pairs, or discordance confined to one parent family, is discovery evidence only. Use it to sharpen a preregistered replication on untouched parents.

### Tested construction negative

If at least **8 exact-resolved admissible pairs across all 3 parents** are phase-distinct but none is LIVE/DEAD, close this specific equal-length topological-fork construction as a negative. Do not conclude that all open-path topology is irrelevant.

### Construction-starved

If fewer than 6 admissible pairs can be frozen across three parents, the pilot is geometry/operator-starved. That is not a representation verdict. Revisit the smallest construction operator before acquiring a larger label campaign.

### Exact-tooling-limited

If more than 25% of frozen pairs lack two resolved exact labels, stop without a representation verdict and address exact-labelling coverage first.

## Guardrails

- No production solver result may influence parent, descendant or prefix-pair acceptance.
- No historical outcome, level ID, family label or exact label becomes a runtime feature.
- A preserved witness proves solvability of the board only; it does not prove the alternate prefix DEAD or the witness prefix uniquely LIVE.
- Keep board mutation minimal. The intervention exists to create a controlled path-history contrast, not to generate hard levels.
- Parent families are the independent units. Descendant/prefix multiplicity does not inflate sample size.
- Do not tune the observer on pilot outcomes. Any representation change after label inspection makes the pilot development evidence and requires fresh-parent replication.
- Do not interrupt the Class-4 canary or Class-2 economics gate to execute this work.

## If the premise advances

The next sequence is:

1. microscope the discordant pairs to determine what completion constraint the topology distinguishes;
2. test whether a smaller runtime-safe generic state summary captures that distinction;
3. run a bounded solver intervention on the smallest nominated population;
4. confirm on untouched independent parents/corpus rows before broad promotion.

If the raw observer separates states but no generic action or pruning/allocation decision follows, stop. Representation without an actionable solver consequence is research evidence, not a production feature.
